# Niche AI Imports

## 目的

ChatGPT / Claude / Gemini だけでなく、Character.AI 系、AIコンパニオン系、ロールプレイ系、ローカルLLMフロントエンド系からも記憶を取り込めるようにする。

ここで拾えるのは、仕事や相談ではなく、以下のような文脈になりやすい。

- 趣味
- 推し
- 創作
- ロールプレイ
- 感情
- 寂しさ
- 恋愛的投影
- キャラクター嗜好
- 物語の好み
- 自分でも表に出しにくい悩み

この領域は高感度なので、初期から慎重に扱う。

## 重要な考え方

すべてのAIチャットサービスが、ChatGPTのように公式ZIPエクスポートを提供しているとは限らない。

そのため、インポート方式を3段階に分ける。

### Tier A: 公式エクスポート対応

公式にデータエクスポートやアーカイブ取得があるもの。

- ZIP
- JSON
- HTML
- CSV

形式検出して、安全に読み込む。

### Tier B: シェア / コピペ対応

公式エクスポートが弱い、または不明なもの。

ユーザーが会話単位で共有・コピーしたものを読み込む。

MVPではここが現実的。

### Tier C: ローカルファイル対応

SillyTavernなど、ユーザーの手元にチャットログやキャラクターカードが存在するもの。

ユーザーが明示的にファイルをアップロードした場合のみ読む。

## 対象候補

### Character.AI

代表的なキャラクターAIサービス。

ユーザーはカスタムキャラクターや公開キャラクターと会話する。

扱う記憶:

- どのキャラと話していたか
- どんな関係性を好んだか
- どんな物語・状況設定を好んだか
- 創作や感情の傾向

注意:

- ロールプレイと本人の現実の価値観を混同しない
- キャラクターの発言をユーザーの記憶として保存しない
- 保存するのは「ユーザーがなぜその会話を大事にしたか」

MVP対応:

- 公式エクスポートが確認できるまでは、シェア / コピペ優先

### Replika

AIコンパニオン系。

感情・孤独・恋愛・依存に近いデータが含まれる可能性が高い。

扱う記憶:

- 当時の感情状態
- 癒やしを求めていた時期
- 自分が大事にしていた関係性

注意:

- 高感度扱い
- 自動保存しない
- ユーザー承認必須
- 他人に見せる前提の出力に混ぜない

### Poe

複数AIモデル・Botを横断して使うサービス。

扱う記憶:

- どのBot/モデルを使ったか
- 相談・創作・調査の履歴
- 複数AIを使い分ける傾向

MVP対応:

- 共有 / コピペ
- 将来、公式エクスポートが確認できればAdapter追加

### Janitor AI / Chub AI / Venus系

ロールプレイ、キャラクターチャット、創作色が強い。

扱う記憶:

- 創作嗜好
- キャラクター関係性
- 世界観
- 感情・恋愛的テーマ

注意:

- NSFWを含む可能性がある
- 未成年保護・年齢制限・ストア審査に注意
- MVPでは積極訴求しない
- インポート可能でも、マーケティング上は前面に出しすぎない

### Kindroid / Nomi / Talkie / PolyBuzz など

AI companion / AI friend / roleplay 系。

サービスごとにエクスポート仕様が変わりやすい。

MVP対応:

- 共通シェア / コピペ
- 公式exportが確認できたものからAdapter化

### SillyTavern

ローカルLLM / ロールプレイフロントエンド。

ユーザーの手元にログやキャラクターカードがある可能性が高い。

扱う記憶:

- キャラクターカード
- チャットログ
- 世界観
- 創作設定

MVP対応:

- JSON / JSONL / TXT / HTMLなどのローカルログアップロード
- フォーマット検出
- 文字コード検出
- キャラクター定義と会話ログを分離

注意:

- キャラ設定はユーザー自身の人格ではない
- 創作物として扱う

## 記憶化ルール

キャラクターAI系のデータは、通常チャットよりも危険に誤解されやすい。

### 保存してよいもの

- ユーザーがそのキャラクターを大事にしていた事実
- 好きな世界観
- 創作テーマ
- 感情の状態
- 当時ハマっていたジャンル
- 自分の書いた設定やプロンプト

### 保存しない、または要承認

- キャラクターの発言を事実として保存すること
- ロールプレイ内容を現実の人間関係として扱うこと
- 性的・暴力的・依存的な内容の自動保存
- 未成年に関わるセンシティブ内容
- 他者の個人情報

## UIでの見せ方

「Character.AIをインポートできます」と前面に出すより、以下の見せ方がよい。

> AIチャットやキャラクター会話から、あなたが大事にしていた設定・感情・創作テーマだけを残せます。

サービス一覧は詳細画面に置く。

初期画面では、入力元を以下のように抽象化する。

- AI相談
- キャラクター会話
- 創作ログ
- SNS投稿
- 写真・予定
- 開発履歴

## Parser設計

キャラクターAI系は形式がバラバラなので、厳密なサービス別実装だけに頼らない。

まず共通のConversationParserを作る。

```ts
type ParsedMessage = {
  role: 'user' | 'assistant' | 'character' | 'system' | 'unknown';
  speakerName?: string;
  text: string;
  timestamp?: string;
};

type ParsedConversation = {
  sourceType: SourceType;
  title?: string;
  characterName?: string;
  messages: ParsedMessage[];
  metadata?: Record<string, unknown>;
};
```

サービス別Adapterは、最終的にこの形へ変換する。

## Safety Classification

キャラクターAI系はデフォルトで高感度寄りに扱う。

```ts
type AiCompanionSensitivity =
  | 'creative'
  | 'emotional'
  | 'romantic'
  | 'nsfw'
  | 'dependency_risk'
  | 'minor_risk'
  | 'unknown';
```

`romantic` / `nsfw` / `dependency_risk` / `minor_risk` は自動保存しない。

## MVP優先順位

1. 汎用シェア / コピペでキャラクター会話を取り込める
2. 会話から「ユーザーが残したい記憶候補」だけ抽出
3. キャラクター発言とユーザー本人の記憶を分離
4. 高感度分類
5. ローカルログアップロード対応
6. Character.AI / Replika / Poe などの個別Adapterは後から

## 結論

ニッチなAIチャットサービス対応は、このサービスの独自性を強くする。

ただし、最初から全サービスの公式エクスポート対応を目指すのではなく、

- 共有
- コピペ
- ローカルログ
- 公式export

をすべて同じConversationParserへ流し込める設計にする。

これにより、新しいAIサービスが出ても、入力Adapterを追加するだけで取り込める。
