# Personal Memory Extraction Rules

## 目的

インポートされたログから、何を「その人の記憶」として残すかを決めるルール。

このサービスはログ倉庫ではない。

会社の便利ツールでも、パスワード管理でも、医療診断でもない。

残すのは、その人を理解するために意味がある文脈。

## 入力から抽出するもの

### 1. Event Memory

人生の出来事。

例:

- 結婚式を挙げた
- 転職を考えていた
- 旅行へ行った
- ゲーム制作を始めた
- 家族と大事な話をした

抽出条件:

- 日付や時期がある
- 人生フェーズに関係する
- 後から振り返る意味がある

### 2. Relationship Memory

人間関係に関する記憶。

例:

- 妻と旅行を大事にしていた
- 父親の考え方に影響を受けていた
- 友人と作品について語っていた

抽出条件:

- 特定人物との関係性が見える
- 共有体験がある
- 感情や価値観が伴う

注意:

相手の性格を断定しない。

### 3. Value Memory

価値観。

例:

- 思い出を残すことを大事にしている
- 面倒なことは続かないと考えている
- 安全性を便利さより優先する
- 品質や世界観を重視する

抽出条件:

- 判断基準として使われている
- 何度も出てくる
- 強い反応がある

### 4. Identity Memory

自己イメージ。

例:

- 自分は継続が苦手だと感じている
- 自分は新しいものを触って判断したい
- 自分は家族や思い出を大事にしたい

注意:

自己イメージは事実ではなく、本人の語りとして保存する。

### 5. Formative Memory

その人を形づくった可能性がある体験。

例:

- 初めて褒められた経験
- 大きな失敗
- いじめ
- 家庭環境
- 作品との出会い
- 結婚や出産
- 喪失

注意:

「これが原因で人格が決まった」と断定しない。

### 6. Taste Memory

好き嫌い・美意識・嗜好。

例:

- ミントグリーンが好き
- 友情や家族テーマの作品が好き
- 怖すぎる表現は苦手
- ドット絵や紙UIが好き

軽く見えるが、その人の安心感・世界観・自己表現に関わるため保存価値がある。

### 7. Pattern Memory

繰り返される行動・思考パターン。

例:

- 最初に大きく構想してから現実的に削る
- コストや継続性を早めに心配する
- セキュリティや安全性に強く反応する
- 便利でも怖いものは避ける

注意:

ラベル貼りしすぎない。

「傾向」として保存する。

### 8. Change Memory

時間による変化。

例:

- 以前はAIの便利さに注目していたが、最近は人生の文脈や継承に関心が移っている
- ゲーム開発から、記憶体サービス構想へ関心が広がった

抽出条件:

- 過去と現在の比較ができる
- 同じテーマで立場や重みが変わっている

### 9. Recovery Memory

回復・支え・立て直しのパターン。

例:

- 相談すると整理される
- 書き出すと前に進める
- 好きな作品やゲームが支えになる
- 家族との会話が安心につながる

注意:

治療法として提示しない。

本人の過去記録として扱う。

## 抽出しないもの

### 1. Secrets

- パスワード
- APIキー
- token
- secret key
- private key
- 認証コード
- クレジットカード番号

### 2. Business Utility

- 社内手順
- 顧客名簿
- 契約条件
- 見積金額
- 本番環境情報
- 業務メール全文

仕事の経験は扱うが、会社の便利情報は扱わない。

### 3. Raw Personal Data Without Meaning

- 電話番号
- 住所
- 予約番号
- 荷物追跡番号
- 請求書番号
- ただのURL一覧

人生文脈に必要な場合だけ、マスクして参照する。

### 4. Other People's Private Data

- 相手の病気
- 相手の悩み
- 相手の住所
- 相手の秘密
- 相手のLINE全文

ユーザー本人の文脈として必要な最小限のみ扱う。

## 抽出時の問い

AIは、各ログに対して以下を問う。

1. これはユーザー本人を理解する役に立つか
2. これは人生の出来事か
3. これは価値観や判断基準を示しているか
4. これは人間関係の文脈か
5. これは時期による変化を示しているか
6. これは将来見返す価値があるか
7. これは高感度すぎて自動保存すべきでないか
8. これは単なる便利情報ではないか
9. これは他人の情報を過剰に含んでいないか
10. これはLLMへ送ってよいか

## MemoryCandidate生成ルール

MemoryCandidateには必ず以下を含める。

- title
- summary
- category
- sourceRef
- evidence span
- why important
- sensitivity level
- confidence
- user approval required

例:

```json
{
  "title": "思い出を残すことへの関心",
  "summary": "この時期、ユーザーはAI時代に自分の人生の文脈を失わないことを強く重視していた。",
  "category": "value",
  "whyImportant": "サービス構想だけでなく、本人の価値観として繰り返し表れているため。",
  "sensitivity": "normal",
  "confidence": 0.82,
  "approvalRequired": true
}
```

## 高感度時の扱い

高感度記憶は、保存候補にはしてもよいが、自動保存しない。

UIでは以下のように表示する。

> この記憶は、家族・健康・お金などの高感度な内容を含む可能性があります。保存する場合は、後から削除・非表示にできます。

## 文章生成ルール

### 良い言い方

- 記録では
- この時期のあなたは
- 何度も出ているテーマとして
- 当時の文脈から見ると
- 推測になりますが

### 悪い言い方

- あなたはこういう性格です
- 原因は親です
- これはトラウマです
- 妻はこういう人です
- あなたは病気です

## まとめ

記憶体は、多くを覚えるほど良いわけではない。

その人を理解するのに必要なものを残し、便利だが本質ではないものを捨てる。

この選別こそが、人生の記憶体の価値になる。
