## Material failure — prospective quoted-delimiter false non-match

- **Symptom:** The earlier multiline-flow guard could treat an opening YAML flow collection as complete if a closing bracket or brace appeared inside a quoted scalar or a quoted `#` fragment. A later alias or event could then be silently missed. This is a prospective static-parser defect, not an observed production incident.
- **Observed evidence:** The reviewed pre-change source used `re.split(r"[ \\t]+#", ...)` followed by a string `endswith` check. A source value like `on: ["fake] # text",` ends the extracted prefix at a `]` **inside** a quoted scalar, even though the flow sequence remains open. Focused Python lexical tests verified 17 complete/incomplete cases including nested delimiters, quoted comments, escaped double quotes and doubled single quotes.
- **Verified root cause:** String suffix checks and comment splitting did not distinguish YAML flow delimiters from characters inside quoted scalars.
- **Failed approach:** Treating the last apparent bracket/brace before a textual `#` as proof of a complete same-line flow value.
- **Correction:** [`85dadd2c`](https://github.com/m-shogo/memories-project/commit/85dadd2c7043d19de100b96de9b13fa0c0a38a92) replaces the suffix heuristic with a bounded quote-aware delimiter stack. It tracks nested flow collections, escaped double-quote characters, doubled single quotes and actual comment boundaries. Unknown or incomplete values remain conservative matches.
- **Executable recurrence guard:** Ten ordered identity-pinned positive/negative flow-lexical cases execute in both the in-process audit self-test and the actual CLI negative suite. Single-line quoted dispatch and nested complete map values remain non-matches, while incomplete quoted/aliased values and malformed closers fail closed.
- **Retry condition:** Revisit only when exact-source CI or reviewed YAML semantics demonstrate a counterexample; do not reintroduce suffix/comment splitting without a changed, verified precondition.
