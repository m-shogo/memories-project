## Material failure A — non-byte Git transport was not rejected uniformly

- **symptom:** The supplemental history Git wrapper previously permitted an apparently successful process result with `stdout` or `stderr` of a non-`bytes` type to pass generic return-code/stderr checks. Some later command-specific decoders rejected malformed data indirectly, but other successful commands did not require a canonical byte stream.
- **evidence:** At corrected exit-status HEAD `b25d42f6`, `git()` checked `result.returncode` and stderr truthiness without a general exact `bytes` check. Isolated `CompletedProcess` controls with `stdout="text"`, `stdout=None`, `stderr=""` and `stderr=None` passed those generic checks. No real Git corruption or production incident was observed.
- **rootCauseOrUnknown:** Verified missing uniform type validation at the external-process transport boundary.
- **failedApproach:** Relying on individual callers' OID grammars or truthiness checks to reject every malformed subprocess stream.
- **correction:** [`32545f7c`](https://github.com/m-shogo/memories-project/commit/32545f7c29771e98bbd64b61fea4f654f4c7828e) rejects any `stdout` or `stderr` whose exact type is not `bytes` before the Git output is consumed.
- **recurrenceGuard:** Four deterministic malformed-stream negatives and a live source AST guard require exact `invalid supplemental Git byte transport` rejection. The CI entrypoint source-negative loop mutates both the predicate and diagnostic, and keeps its 4,095-line prewrite-positive headroom.
- **retryCondition:** Revalidate on Git subprocess wrapper, stream type, CI entrypoint AST binding or fixture changes. Do not retry unchanged external MinIO or permission blockers.
