## Material failure 1 — unreviewed composed input paths

- **Symptom:** The Upload Route Python input fingerprint tracked full `"contracts/..."` / `"docs/..."` source literals but could miss new paths built as `Path("contracts") / "operations/new.json"`, `ROOT / "docs" / ...`, `ROOT.joinpath("services", ...)` or `os.path.join("scripts", ...)`. This was a potential static dependency-inventory escape, not an observed production incident.
- **Observed evidence:** The prior source scanner extracted only complete prefix-plus-slash string literals and rejected dynamic imports/process launchers. The four reviewed Python validators did not use the listed split-root patterns, but the negative suite lacked them.
- **Verified root cause:** A full-literal SHA-256 fingerprint cannot detect file paths composed from separately quoted root and child segments.
- **Failed approach:** Treating unchanged full-path literal sets as a self-updating complete runtime-input inventory.
- **Correction / executable recurrence guard:** [3d538dc7](https://github.com/m-shogo/memories-project/commit/3d538dc77fc1d96076f9b23326e23b131e5d4688) adds conservative AST checks for `Path`/`PurePath` repository-root arguments, `/` joins, `joinpath` and `os.path.join` with root segments. Four synthetic negative cases reject split-root composition, while a benign temporary-directory join remains an explicit positive control. The previously reviewed 109-path lower-bound set and 81 uncovered paths per Upload Route workflow remain separately fingerprinted; no claim of complete dynamic/external dependency closure is made.
- **Retry condition:** Re-review legitimate new path-composition semantics with real source/input evidence, exact-source CI and protected-authority checks. Do not change Upload Route event filters without complete dependency closure and authorization.
