## Material failure 1 — inherited PATH could redirect supplemental Git history inspection

- **symptom:** The supplemental history guard launched `subprocess.run(["git", "-C", ...])`, so an inherited PATH with a writable earlier directory could resolve to a decoy executable instead of the trusted Git binary. This is a verified source-level trust-boundary gap and synthetic executable-resolution proof, not an observed production compromise.
- **evidence:** Before `11474a79`, `git()` stripped inherited `GIT_*` variables and pinned Git configuration but still invoked bare `git`. An isolated executable-resolution test demonstrated that a decoy named `git` earlier on PATH returned `FAKE_GIT`, while `/usr/bin/git` returned its real version.
- **rootCauseOrUnknown:** Verified executable lookup by inherited PATH; no repository-specific attacker control or actual exploit is asserted.
- **failedApproach:** Treating environment sanitization of `GIT_*` variables as sufficient when the Git executable itself remained unpinned.
- **correction:** [`11474a79`](https://github.com/m-shogo/memories-project/commit/11474a79127bd67757e630aa6e6a5fce00318ed0) binds the history wrapper to `TRUSTED_GIT = "/usr/bin/git"`, leaving deliberately untrusted `subprocess.run(["git", ...])` only inside negative controls. This assumes a reviewed Ubuntu/macOS host with root-owned `/usr/bin/git`; a different runner image must be reviewed rather than silently falling back to PATH.
- **recurrenceGuard:** The existing 39-fixture supplemental history suite now creates a disposable PATH-first decoy, proves naive lookup resolves to it, and requires the canonical wrapper to return the real Git version. [`29d10b33`](https://github.com/m-shogo/memories-project/commit/29d10b33a27edc875a4977bec02acb5d2b634c25) additionally AST-binds the unique trusted executable assignment and the live subprocess call; [`e1f00239`](https://github.com/m-shogo/memories-project/commit/e1f0023907537a901642171cf0d2bbe253274c77) adds valid-Python negative mutations for a bare-Git call and a shadowed trusted executable.
- **retryCondition:** Revisit on reviewed CI runner/OS Git path changes, a new executable resolution or alias mechanism, or exact-source regression. Do not retry unchanged external MinIO HTTP 401, workflow write-permission or human-evidence blockers.

## Material failure 2 — escaped shell fixture was not a real executable negative

- **symptom:** The initial new PATH-decoy fixture wrote literal backslash-n sequences rather than shell newlines. A successful source update was not sufficient proof that the injected decoy script was executable.
- **evidence:** Post-write source inspection found double-escaped Python string sequences in the fake script and expected stdout. A separate isolated Python/shell reproduction established that the corrected `#!/bin/sh\n...` fixture returns exit 0 and exactly `b"DECOY_GIT_EXECUTED\n"`.
- **rootCauseOrUnknown:** Verified double escaping during generated source-string construction; not a Git history failure.
- **failedApproach:** Trusting a generated fixture's string escapes without checking the resulting Python source and shell output.
- **correction:** [`f399821d`](https://github.com/m-shogo/memories-project/commit/f399821db723433348b7acebe186febc431e9c6f) corrected the fixture before its first exact-source CI success.
- **recurrenceGuard:** Require a working decoy positive control before asserting that the trusted wrapper rejects PATH substitution; the CI-reachable suite now checks the exact decoy stdout, real-Git output and environment restoration.
- **retryCondition:** Revisit on changes to shell fixture construction, platform shell semantics or expected decoy transport.
