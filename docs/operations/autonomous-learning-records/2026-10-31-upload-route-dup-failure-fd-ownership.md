## Material failure — newly introduced dup-failure cleanup gap

- **symptom:** A new staging-inode pin added in `5ede2d8c` duplicated the `mkstemp` descriptor before `fdopen`. If `os.dup` failed, the exception handler closed the only original descriptor before the outer cleanup, while `staged_identity` was still `None`. The outer cleanup therefore skipped the temporary file. This was a source-verified latent exceptional-path residue gap, **not** an observed production failure.
- **evidence:** At `so` `125c1d0fe440c022aa78f0e1b4ef55cd2e343a6a`, `atomic_write_bytes` assigned `staged_identity` only after the `try: os.fstat; os.dup` block. The `except BaseException` closed `descriptor` before re-raising, and the `finally` guarded cleanup with `staged_identity is not None`. A disposable local OS probe confirmed that retaining the original descriptor until name cleanup prevents inode reuse and allows the temporary file to be removed after a synthetic dup failure; that probe is not production evidence.
- **rootCauseOrUnknown:** Verified resource-ownership ordering gap: the original descriptor was released before cleanup could establish the staged file's identity. Whether `os.dup` ever fails on a real runner under normal operation is unknown.
- **failedApproach:** Adding a pinned duplicate for successful staging while assuming the pre-`fdopen` duplication-failure branch could safely close the only descriptor immediately.
- **correction:** [`ba69c90e`](https://github.com/m-shogo/memories-project/commit/ba69c90e6426ff144b6c589b89937d537bec7288) captures `staged_identity` before duplication, retains `untransferred_stage_fd` through the outer cleanup until `fdopen` owns it, and closes the raw descriptor in an unconditional nested `finally`. The successful `fdopen` and failed acquisition branches clear the raw ownership marker, while the duplicate staging pin remains separately closed after cleanup.
- **recurrenceGuard:** The same commit adds directly invoked `prove_atomic_dup_failure_cleanup` to the existing MinIO-free rollback negative harness. It faults the actual `os.dup` transport after a real `mkstemp`, requires the exact failure, checks `EBADF` on the original descriptor after cleanup, verifies unchanged original bytes and 0755 mode, and requires no temporary residue. The existing read-only CI entrypoint binds this proof to a direct `main()` call and actual writer transport; AST/source mutation negatives reject missing dup-fault injection, removal of the retained raw-FD close, or loss of the pinned staging close.
- **retryCondition:** Revisit on changed staging FD ownership, `os.fstat`/`os.dup`/`fdopen` transport, atomic cleanup, exact-source CI reachability or platform semantics. If the initial `os.fstat` itself fails before identity capture, the current code fails closed and closes the raw FD but may retain a staging pathname; this separate residual needs reviewed identity-safe cleanup, not a blind pathname unlink.
