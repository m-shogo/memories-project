## Material semantic gap / failure

- **symptom:** The prewrite fanout auditor could undercount a push/PR trigger expressed as a YAML block sequence or an inline alias rather than a literal `on: push` or `on: [push]` token.
- **evidence:** [GitHub workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#on) supports event arrays, and [GitHub reusing workflow configurations](https://docs.github.com/en/actions/reference/workflows-and-actions/reusing-workflow-configurations#yaml-anchors-and-aliases) documents YAML anchors/aliases. The previous read-only parser searched for root `on:` and nested event mapping keys, but not `on:\n  - push` or `name: &trigger push\non: [*trigger]`. This was a static parser blind spot, not an observed production incident.
- **rootCauseOrUnknown:** Verified parser omission for block event-list rows and inline YAML alias tokens; no external production cause is claimed.
- **failedApproach:** Treating event arrays only as inline literal `on: [push]` and aliases only as direct `on: *events` while assuming absence of literal event names meant no push/PR trigger.
- **correction:** [`dfce64f6`](https://github.com/m-shogo/memories-project/commit/dfce64f672b3299f9507b682534a1b967f4452fe) conservatively detects inline aliases and block event lists, preserving a negative control for dispatch-only lists and classifying unreviewed list entries as possible push/PR events.

Exact ordered fixture identities are now pinned at 52 audit and 35 CLI cases. The existing CI checks real checked-out workflow identities and risk classifications.
