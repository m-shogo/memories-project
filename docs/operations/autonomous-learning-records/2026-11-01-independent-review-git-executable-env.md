- **symptom:** The generation independent-review validator's three read-only Git history/blob subprocesses used bare `git` and inherited Git/dynamic-loader settings. Their 20-second bounds, strict exit/output checks and append-only comparison did not establish the executable's identity.
- **evidence:** At source blob `35c3eb8a`, `git log`, `git cat-file -s` and `git show` used `["git", ...]` without explicit environment sanitization. The existing negative suite asserted the bare executable and therefore did not reject PATH resolution spoofing. A disposable PATH-first Git can emit a syntactically valid SHA; no real compromised runner, forged review, recovery candidate or production evidence was observed.
- **rootCauseOrUnknown:** Verified source-level executable and inherited environment trust boundary. Actual adversarial control is unknown.
- **failedApproach:** Treating bounded private Git output and exact SHA syntax as sufficient independent-review provenance without a pinned executable and sanitized environment. The prior double-escaped shell negative failure was avoided by checking generated fixture source before writing.
- **correction:** Atomic commit [`7f61bbe0`](https://github.com/m-shogo/memories-project/commit/7f61bbe04bbfde7156ceae9d046592e090e4bf35) pins all three calls to `/usr/bin/git`, supplies a shared environment that strips inherited `GIT_*`, `LD_*` and `DYLD_*`, disables replace objects and system/global config, and includes the helper and executable identity in existing execution-authority bindings. The two-commit history limit, 20-second timeout, exact blob bytes and append-only review rules are preserved.
- **recurrenceGuard:** The existing independent-review negative suite now requires the pinned executable and sanitized environment for history, size and blob reads. A real disposable PATH decoy must first emit a valid forged 40-hex SHA, then the live reader must reject a nonexistent synthetic review for the exact committed-evidence reason.
