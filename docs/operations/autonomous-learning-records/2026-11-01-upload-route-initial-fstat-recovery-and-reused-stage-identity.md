## Material failure risk — first staged fstat fails before the stage identity is captured

- **symptom:** A newly created descriptor-relative Upload Route temporary file could remain under its private name if the first `os.fstat(descriptor)` raised before `staged_identity` was assigned. The finalizer had no verified inode identity and correctly avoided unlinking an unverified name, but did not attempt safe recovery of an identity from the still-open owned descriptor. This is a source-verified latent cleanup gap, **not** observed production leakage.
- **evidence:** Starting `so` `7bb3c9d841b1c06234c9291e3bbfc91da5b96f8f`, `atomic_write_bytes` captured `staged_identity` only after its initial `os.fstat(descriptor)`, and its finalizer cleaned only if that identity was non-null. The preceding supplemental learning `2026-11-01-upload-route-pinned-stage-hardlink-and-scoped-reader-negative.md` already required a single-link pinned stage and an independent stage-name owner guard; these protections were reused.
- **rootCauseOrUnknown:** Verified absence of a descriptor-based recovery attempt in the pre-identity failure path. The frequency and causes of actual filesystem `fstat` failures in deployment are unknown; no live production incident is asserted.
- **failedApproach:** Relying only on the first `fstat` to populate cleanup ownership, or inferring ownership from the temporary pathname after that `fstat` fails. The latter could unlink a new independent owner if the name is reused.
- **correction:** [`0542b344`](https://github.com/m-shogo/memories-project/commit/0542b3443c305ff5b40c3e9304c18b6f0cd1414b) attempts a second `os.fstat(untransferred_stage_fd)` in the finalizer **only** when the original descriptor is still owned and no stage identity was captured. It permits cleanup only for a regular single-linked inode and only when the descriptor-relative live temporary name still has the same device/inode. If recovery fails or ownership cannot be verified, it leaves the unverified name untouched rather than risking deletion of independent data.
- **recurrenceGuard:** [`361102e5`](https://github.com/m-shogo/memories-project/commit/361102e5a43255463326cdec09a47188ea0149f4) adds an executable disposable failure-injection negative for a transient first-`fstat` error and for a reused temporary name; [`f2b34cb2`](https://github.com/m-shogo/memories-project/commit/f2b34cb2cae2adb3b22e3702f8a1a8218f22f28d) adds a retained hardlink to the original stage before the name is replaced, forcing the recovered descriptor to remain single-linked while the new pathname belongs to an independent canary. These tests require the original authority bytes/mode to remain unchanged, all staged descriptors to close, a recoverable owned stage to be cleaned, and both independent canary and retained original inode to survive. [`5610eaaf`](https://github.com/m-shogo/memories-project/commit/5610eaaf1c183ac2e7c9af14e1a205f2f94ef06f) and [`b3edc25e`](https://github.com/m-shogo/memories-project/commit/b3edc25e109413a2e4108564595f9903b68d80c3) bind the proof to the existing pre-MinIO entrypoint and add a source-negative mutation that weakens the recovered stage's single-link predicate. The entrypoint remains within its existing 4,096-line prewrite limit.
- **retryCondition:** Revisit if the stage descriptor lifecycle, no-follow directory semantics, link-count policy, CI source binding, or exact-source validator outcome changes. A permanently failing `fstat` cannot establish safe unlink ownership; leaving an unverified private stage is an explicit fail-closed residual boundary. The final check to rename is still not an atomic leaf CAS.
