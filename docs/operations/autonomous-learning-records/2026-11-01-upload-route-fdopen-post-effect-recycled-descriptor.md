## Material failure class — ambiguous fdopen acquisition can consume a descriptor

- **symptom:** The old `atomic_write_bytes` exception handler unconditionally called `os.close(descriptor)` when `os.fdopen(descriptor, "wb")` raised. If fdopen had already closed the FD and its numeric value was reused by an independent file, the cleanup could close the unrelated owner. This is a source-proven latent race, **not** an observed production incident.
- **evidence:** The pre-change `605a243e` source called `os.close(descriptor)` without checking its identity. The new disposable negative covers `before-fdopen`, `after-fdopen-closed` and `after-fdopen-reused`; the last closes the original FD, reuses its numeric value for an independent canary, and requires that canary FD to remain open. The baseline code was not separately run with this new fixture, so no baseline runtime failure is asserted.
- **rootCauseOrUnknown:** Verified ambiguity in FD ownership after a raising stream constructor; an exception does not establish whether the constructor consumed the descriptor.
- **failedApproach:** Unconditional cleanup by a stale numeric descriptor after failed fdopen acquisition, even with a broad `OSError` catch.
- **correction:** [`69662b18`](https://github.com/m-shogo/memories-project/commit/69662b18db882e00db5d9b318a792ef37323fed3) first probes the numeric descriptor with `fstat` and compares its device/inode to the pinned staged identity. It closes only when this bounded identity matches, otherwise skips the close and adds a bounded ownership diagnostic; a failed probe is also noted. The stage guard FD remains independently owned and the outer cleanup does not retry an uncertain untransferred FD.
- **recurrenceGuard:** Three real-filesystem scenarios with a recycled-number canary, original byte/mode and residue checks, plus a live main-call AST binding and source-negative mutations that remove the fault injection, remove the recycled case, or bypass the identity probe/diagnostic. The CI entrypoint remains below its 4,096-line limit.
- **retryCondition:** Revalidate if fdopen acquisition/ownership, staged inode identity, guard-FD cleanup, source-negative reachability or Python FD semantics change. The `fstat`-then-`close` check is **not an atomic FD compare-and-swap** and does not prove safety against arbitrary concurrent descriptor reuse between those operations; revisit with a separately proven ownership protocol before asserting a stronger guarantee.
