## Material failure: symptom, observed evidence, root cause, failed approach, correction, recurrence guard, retry condition

- **Symptom / observed evidence:** The new supplemental all-parent history guard used `git -C <root>` but inherited `GIT_DIR` and `GIT_WORK_TREE` from the caller. An isolated two-repository Git reproduction showed that each selector redirected `git -C trusted rev-parse --show-toplevel` to the **decoy** directory, despite `-C trusted`. The corrected environment returned the trusted directory in both cases.
- **Verified root cause / failed approach:** `env = dict(os.environ, GIT_NO_REPLACE_OBJECTS=..., GIT_CONFIG_NOSYSTEM=..., GIT_CONFIG_GLOBAL=...)` retained hostile `GIT_*` selectors. Assuming `-C` and a disabled global/system config alone established repository identity was unsafe.
- **Correction / executable recurrence guard:** [4cd078ff](https://github.com/m-shogo/memories-project/commit/4cd078ffe696fac4969689500900cff5366e31da) filters inherited `GIT_*` variables before explicitly setting reviewed no-replace/global/system configuration. Two independent self-test fixtures inject `GIT_DIR` and `GIT_WORK_TREE` pointing at a decoy repository; both must preserve the trusted Git root. The existing 21 scoped/merge fixtures and two delimiter-literal fixtures remain intact (25 total).
- **Retry condition:** Revisit only if the Git invocation environment, trusted repository binding, all-parent history topology or exact-source CI changes. Do not retry unchanged MinIO HTTP 401, workflow-write permissions, canonical 4.17 MB contents-API write, or human-promotion blockers.

## Material tool orchestration failure and bounded correction

- **Symptom / evidence:** An initial combined connector transaction exceeded the maximum tool-call budget before a branch-ref update. A fresh `so` read confirmed the old HEAD `11b7478e` remained authoritative. No unverified intermediate object was claimed as published.
- **Root cause / failed approach:** Too many branch/file rereads and Git-object writes were combined into one connector orchestration despite prior learning about bounded connector operations.
- **Correction / recurrence guard:** Split publication into small independently verified stages: reread HEAD and target before each blob, tree and commit; then reread both targets and active writers before a non-force CAS ref update with `expected_sha`. The final ref advanced from `11b7478e` to `4cd078ff` only after the CAS succeeded.
- **Retry condition:** Use staged calls when the tool-call budget is unchanged. Never replay the oversized all-in-one transaction or assume an orphan Git object changed `so`.
