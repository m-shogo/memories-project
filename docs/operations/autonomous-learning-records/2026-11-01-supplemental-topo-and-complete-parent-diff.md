## Material failure A — same-count interior commit substitution

- **symptom:** A syntactically valid `rev-list --reverse` stream could replace an interior commit OID with another unique OID while retaining the original number of entries and the terminal HEAD. Count, uniqueness and final-HEAD checks alone would accept the enumeration. This is a source-proven latent audit gap, not evidence of an actual Git history rewrite.
- **evidence:** Before [e8138b55](https://github.com/m-shogo/memories-project/commit/e8138b5586cf5e0df271ca4798a4b8086c633553), `check_history` compared `rev-list --reverse` only with `rev-list --count` and the terminal HEAD. A disposable three-commit Git probe confirmed that a distinct baseline OID can replace the middle entry while preserving length, uniqueness and final HEAD; a separately ordered genuine range has a different set.
- **rootCauseOrUnknown:** Verified incomplete membership proof; independent Git command trust, local reflog integrity and remote atomic ref CAS remain separate limitations.
- **failedApproach:** Infer complete commit membership from a count, distinct entries and a matching final OID.
- **correction:** [e8138b55](https://github.com/m-shogo/memories-project/commit/e8138b5586cf5e0df271ca4798a4b8086c633553) adds a separately ordered `rev-list --topo-order` stream and requires equal length and exact OID set; [d7f6b6f1](https://github.com/m-shogo/memories-project/commit/d7f6b6f10f1cacca90becccb8688df10472844c9) tightens its source-negative call-site target.
- **recurrenceGuard:** A real disposable three-commit fixture injects same-count middle substitutions into each of the two enumeration transports, requires the exact incomplete-enumeration diagnostic, and restores a positive. The Git wrapper validates the independent stream's raw OID format. The CI-reached AST/source-negative guard binds the live independent call and both comparisons.
- **retryCondition:** Revalidate if enumeration flags, count logic, parent traversal, source-negative binding, Git version semantics or the trusted local Git transport changes. Do not infer a tamper-proof witness or remote CAS from the independent check.

## Material failure B — nonempty diff confirmation omitted a modification

- **symptom:** A forged `diff-tree --name-status -z` stream containing one real added file but omitting a simultaneous modification would still agree with the old `git diff --quiet` result that *some* scoped change existed. The omitted protected modification could be missed. No production/history mutation was observed.
- **evidence:** Before [8ca7c4ea](https://github.com/m-shogo/memories-project/commit/8ca7c4ea7d5040cdcbafb91bef452716e9efa754), confirmation checked only empty/nonempty agreement. A disposable mixed A/M Git commit produced both statuses; suppressing M while retaining A leaves the old boolean confirmation unchanged. Local Git comparisons also showed byte-identical full name-status streams across A/M/D, mode/symlink and both merge-parent edges.
- **rootCauseOrUnknown:** Verified information loss from reducing the independent diff to a boolean. A common-mode compromise of the trusted Git executable remains outside this proof.
- **failedApproach:** Treat nonempty `diff-tree` and `git diff --quiet` as proof of complete per-path status enumeration.
- **correction:** [8ca7c4ea](https://github.com/m-shogo/memories-project/commit/8ca7c4ea7d5040cdcbafb91bef452716e9efa754) compares the complete NUL-delimited `git diff --no-ext-diff --no-textconv --no-renames --name-status -z` stream with `diff-tree` for each parent edge, and rejects nonzero, malformed or diagnostic-bearing confirmation.
- **recurrenceGuard:** A real mixed A/M parent-edge negative injects a partial but syntactically valid `diff-tree` stream and requires exact enumeration-incomplete rejection. Existing empty-diff, malformed-result and independent-diff negatives remain; the AST guard pins the complete confirmation body and source-negative mutations.
