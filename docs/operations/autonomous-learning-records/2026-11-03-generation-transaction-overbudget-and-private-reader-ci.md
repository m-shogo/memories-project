## Material failure — over-budget and non-OS source-read boundary

- **symptom:** The independent generation-evidence registry transaction negative harness could continue a read loop with a negative byte budget when a mocked `os.read` returned more than requested. Its pinned writer importer normalized `OSError` but could expose a private `ValueError` or `TypeError` from the same syscall boundary.
- **evidence:** At initial `so` HEAD `28a3b744f7a39f7a51a8349cfbb2ee04cfc48f86`, `pinned_writer_source` used `while remaining:`, subtracted `len(chunk)` without first requiring `len(chunk) <= remaining`, and caught only `OSError`. The test harness covered EOF/nonbytes/OSError but no over-budget or non-OS exception. The over-budget loop risk follows directly from Python's truthiness of negative integers; **no observed CI hang, real kernel over-read, private disclosure or production incident is claimed**.
- **rootCauseOrUnknown:** Verified missing per-chunk budget check and incomplete syscall exception normalization in this distinct pinned importer. Real-world exploitability is unknown.
- **failedApproach:** Relying on a final source-size check after a decrementing `while remaining` loop, and assuming `OSError`-only handling or neighboring transport tests protect this separate importer. Prior `2026-11-02-generation-reconciler-oversized-read-loop-correction.md` explicitly prohibits adding an over-budget negative before the reader can terminate.
- **correction:** [`28eaaa48`](https://github.com/m-shogo/memories-project/commit/28eaaa48b9cbb21a60b5ed6f8051d6f63abd28ec) changes the loop to `while remaining > 0`, checks `len(chunk) <= remaining` before decrement, and normalizes `(OSError, ValueError, TypeError)` to the fixed private `pinned source unreadable` domain failure.
