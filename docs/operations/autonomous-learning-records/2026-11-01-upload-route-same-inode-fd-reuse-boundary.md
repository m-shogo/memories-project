# Supplemental OPS learning — same-inode FD-number reuse defeats fdopen cleanup ownership inference (2026-11-01)

This is append-only execution learning under `contracts/operations/autonomous-learning-system.json` and the canonical `docs/operations/AUTONOMOUS-OPS-LEARNING.md`. **It is not** production, backup/restore, RPO/RTO/skew, drill, credential, traffic, readiness, environment-generation, approved-objective, reviewed-request, request-bound recovery, typed eight-domain non-resurrection, independent-review, final-candidate or human-promotion evidence.

## Material failure / unresolved safety boundary

- **symptom:** The Upload Route reconciler's exceptional `fdopen` cleanup may close a numeric FD now owned by an independent opener even when the reopened FD points to the **same inode** as the original staged file. This is a verified ownership-inference flaw in source, **not** an observed production incident.
- **evidence:** On starting branch `so` HEAD `b52120bf48f00d7328305695470d89a4dbfeaff2`, `scripts/reconcile-memory-os-upload-route-authority.py` blob `69dcdf3abd7a2881d07ac9a7eff44634518446b2` checks `fstat(descriptor)` and compares only `(st_dev, st_ino)` to `staged_identity`, then calls `os.close(descriptor)` on equality. The existing disposable negative covers a recycled FD to a *different* inode, not same-inode reopening. A local isolated POSIX test created a staged regular file, duplicated the original FD as a guard, closed its numeric FD, reopened the same path into that numeric slot, and observed both the same numeric FD and equal `(st_dev, st_ino)` for the **independently reopened** descriptor. This proves the identity predicate cannot distinguish ownership; it does **not** prove a production race occurred.
- **rootCauseOrUnknown:** Verified: device/inode identity establishes file-object identity, not descriptor *ownership*. An independent same-inode open or dup can satisfy the existing predicate. Whether such a race is reachable during an actual failed `fdopen` invocation remains unmeasured; arbitrary concurrent FD reuse between `fstat` and `close` also remains non-atomic.
- **failedApproach:** Treat `fstat` device/inode equality (even with a separately pinned guard FD) as authorization to close a possibly recycled numeric descriptor after an ambiguous `fdopen` failure. A different-inode recycled-canary negative alone does not close this gap.
- **correction:** **Not yet applied to runtime.** Reclassify this as an unresolved ownership boundary rather than a proven safe close. The next code change must use a protocol that never closes an uncertain numeric FD after ambiguous handoff, explicitly account for the possible FD leak on pre-effect failure, and preserve original exception, stage-name cleanup, pinned-parent and external-canary guarantees. Do not assert atomic FD CAS or silently remove existing negative coverage.
- **recurrenceGuard:** Proposed executable, CI-bound real-filesystem negative: inject a post-effect `fdopen` failure that closes the original numeric descriptor and reopens the same staged inode into that number; assert that the independent replacement FD stays open and unchanged, the original authority is unchanged, the stage name is cleaned up, and the primary error survives. Add a distinct pre-effect positive/control and source-negative mutation so deleting the case or reintroducing `os.close(descriptor)` fails closed. **This guard is not yet implemented or CI-validated.**
- **retryCondition:** Change only after rereading latest `so`, the reconciler, disposable rollback negative, AST/source-negative entrypoint and prior fdopen lessons; require a complete revised ownership protocol and a CI-reachable same-inode negative. Do not retry unchanged MinIO HTTP 401 or workflow-write permission blockers.

## Material safe research success

- **outcome:** Independently reproduced the exact false-positive identity predicate in a disposable local temporary directory; no repository production file, credential, traffic, registry or authority was modified by the reproduction.
- **evidence:** Local Python POSIX reproduction returned `same_numeric_fd=True`, `same_inode=True` and `same_file_mode=True` after close/reopen/dup2. The independently reopened FD and the retained guard were explicitly closed at the end of the isolated test. Existing learning `2026-11-01-upload-route-fdopen-post-effect-recycled-descriptor.md` already identifies the non-atomic `fstat`/close boundary; this record narrows it to a concrete same-inode false positive.
- **whySafe:** The reproduction used a temporary regular file and its own descriptors only; no production or backup/restore evidence was created and no readiness gate was exercised.
- **reusableMechanism:** Distinguish descriptor number, inode identity and ownership as separate concepts. In ambiguous resource handoffs, an equality check on the underlying object cannot prove that the caller still owns the numeric handle.
