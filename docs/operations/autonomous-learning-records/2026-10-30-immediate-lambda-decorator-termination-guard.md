## Material failure — prospective CI guard reachability bypass

- **Symptom:** A valid `validate_learning_guards(failures)` call and a canonical `if __name__ == "__main__"` entry guard can remain in the AST while an immediately invoked lambda or an eager lambda decorator terminates the process first.
- **Observed evidence:** At reviewed source `c099c200b31b96e36b3b67288f4cb47d3ca80265`, `can_terminate_before_guard` deliberately skipped deferred `ast.Lambda` bodies, but did not distinguish `(lambda: sys.exit(0))()` from a deferred lambda or `@(lambda fn: os.abort())` from a benign decorator. The existing negative inventory covered direct, reflective, dictionary and operator-factory termination but no immediately invoked lambda or terminating lambda decorator. This is a static guard gap, **not** observed CI compromise or a production incident.
- **Verified root cause:** Python evaluates immediately called lambda bodies and applies lambda decorators while defining functions/classes. The reachability visitor modeled lambdas only as deferred declarations, even at those eager evaluation sites.
- **Failed approach:** Inferring execution reachability from syntactically present live guard calls while treating every lambda body as deferred; blindly traversing every lambda body would incorrectly reject safe deferred declarations.
- **Correction:** [`ac1a9af8`](https://github.com/m-shogo/memories-project/commit/ac1a9af89e6d4d781acf2da2787e11c2bdc5e180) extends the existing read-only AST reachability check to inspect immediately called lambda bodies and eager lambda decorators on function, async-function and class definitions.
- **Executable recurrence guard:** Six isolated canonical negatives reject three eager termination forms before the module main guard and three before the learning guard call. Each requires the correct first diagnostic. Three additional positive controls preserve deferred lambda termination, a benign immediately invoked lambda and a benign lambda decorator.
- **Retry condition:** Revisit a legitimate eager lambda termination only with changed reviewed control-flow requirements, source/HEAD revalidation, exact-source CI, positive/negative diagnostic identity and protected-authority verification. This guard does not prove arbitrary Python alias closure or the Go/Python transitive dependency closure.
