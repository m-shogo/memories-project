- **symptom:** The two drill-generation-binding planning JSON loaders read authority bytes through `path.open("rb")` after an earlier runtime path check, without pinning each ancestor directory or comparing descriptor and pathname identity across the read. A symlink substitution or in-place mutation between validation and read lacked executable negative proof.

The existing strict JSON negative suite covered duplicate keys, nonfinite numbers, oversized integers and bytes, but not path acquisition, parent/leaf symlinks, hardlinks or mid-read mutation. No production attack or corruption was observed.
- **rootCauseOrUnknown:** Verified path/descriptor TOCTOU and negative-proof gap in the two planning JSON readers; exploitation in a real environment is unknown.
- **failedApproach:** Treating initial `enforce_runtime_authorities()` and strict JSON parsing as sufficient protection for a later mutable-path read.
- **correction:** [`d7357637`](https://github.com/m-shogo/memories-project/commit/d73576370d8ce2bc6e4961e04d175c4932ec8149) replaces both reads with bounded, no-follow directory-FD traversal, a single owned source FD, regular-file/single-link checks, raw-read type and size checks, pre/post descriptor/leaf identity, ancestor pathname identity, and primary-error-preserving FD cleanup.
