## Material failure — prospective prewrite check/read separation

- **symptom:** The Python prewrite CLI checked `Path.is_file()`, parent symlinks and `Path.stat().st_size` but subsequently read baseline/candidate with unbounded `Path.read_text()`. A hardlinked or world-writable candidate could pass the previous checks, and a file swapped between the size check and read could bypass the byte limit or block as a FIFO. This is a prospective source-integrity gap, not an observed production incident.
- **evidence:** At starting HEAD `a54e6ce048955878e1a2c62f794a539849fd3728`, `validate_prewrite_files` used separate size preflight and path-based `read_text()`. Prior `2026-10-30-learning-canonical-descriptor-pinned-read.md` provided an existing bounded descriptor mechanism; `2026-10-30-prewrite-bounded-fd-workflow-source.md` established the same failure mode for workflow YAML.
- **rootCauseOrUnknown:** Verified source check/read separation and missing hardlink/world-write identity enforcement for prewrite Python inputs. Actual exploitation and concurrent replacement were not observed.
- **failedApproach:** Treating a prior path size/type check as an immutable guarantee for a later unbounded source read.
- **correction:** [`6a9854f5`](https://github.com/m-shogo/memories-project/commit/6a9854f5fe5b81d8c091f5cab01288653c467686) reuses the reviewed `read_canonical_authority_bytes` mechanism for both prewrite baseline and candidate with a 512 KiB limit, nonblocking/no-follow descriptor checks and the same stable-byte parse path. It preserves the prewrite oversize and invalid UTF-8 diagnostics while introducing a distinct unsafe source-identity rejection.
