## Material failure

- **symptom:** Two drill-generation-binding planning JSON readers pinned absolute ancestor directories and file identity, but did not reject group/world-writable checkout-local parent directories or detect permission changes in their pinned parent descriptors. A writable parent could undermine the trusted pathname authority before acquisition. No production attack or corruption was observed.
- **evidence:** At `so` HEAD `d9b70c29`, both `load(path)` functions used `O_NOFOLLOW` traversal and inode checks, but did not check checkout-local ancestor `st_mode` or include directory mode/ctime in their final pinned-parent identity. The established negative suite lacked writable-parent and mid-read chmod fixtures.
- **rootCauseOrUnknown:** Verified parent-directory permission authority gap; actual exposure in a production checkout is unknown.
- **failedApproach:** Relying on no-follow traversal and stable inode alone to establish trusted planning JSON authority without checking whether a directory was writable by another group/user. An initial attempted source rewrite was safely aborted before any Git write because its expected log-string anchor was stale; the exact current negative-suite line was re-read before retry.
- **correction:** [`0d2a6afa`](https://github.com/m-shogo/memories-project/commit/0d2a6afa105c2805c0bf7fffe812f8bc16903188) requires checkout-local absolute planning paths, checks pinned checkout-root and descendant directory modes before leaf acquisition, and compares pre/post descriptor and lexical `lstat` identity including mode/ctime after reading. External sticky-writable ancestors such as `/tmp` are not treated as checkout authority.
- **recurrenceGuard:** The existing CI-reached drill-generation-binding reconcile negative suite now requires both JSON readers to reject writable fixture-root and authority-parent directories and a parent chmod during pinned `os.read`. It restores modes after each isolated fixture, retains the fragmented-read positive case, and checks canonical authority bytes remain unchanged. Patch creation also requires unique exact source anchors and re-reads target files and `so` before Git CAS.
- **retryCondition:** Revisit only when checkout path policy, filesystem permission/identity assumptions, JSON reader source, negative fixture text or exact-source CI changes. Do not retry unchanged Quay MinIO HTTP 401, workflow-write permission or absent real production evidence blockers.
