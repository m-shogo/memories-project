## Material failure class — post-effect publication probe failure lacked executable fault coverage

- **symptom:** The upload-route atomic replacement negative exercised before-effect and after-effect `os.replace` exceptions, but did not exercise an independent failure of the diagnostic `os.stat` after the replacement had already taken effect. The primary replacement error and uncertain publication note could therefore regress without that specific runtime fault being caught.
- **evidence:** At source HEAD `d5de1773`, `prove_atomic_replace_failure` iterated only `("before-effect", "after-effect")`. The reconciler had an `except Exception as probe_exc` branch for a failed post-replace `os.stat`, but no disposable after-effect probe-failure case. This was a verified test-coverage gap, not a production incident.
- **rootCauseOrUnknown:** Verified: diagnostic probe failure was absent from the existing executable replacement fault matrix. Real production occurrence and impact are unknown.
- **failedApproach:** Assuming a successful post-effect diagnostic probe plus source-string binding established original-error preservation when the probe itself fails.
- **correction:** [bf4bba1b](https://github.com/m-shogo/memories-project/commit/bf4bba1b52a701b74ae1dbfc2e634b9283ef0a0a) adds `after-effect-probe-failure` to the disposable test. The injected `os.replace` first performs the actual rename and raises; a scoped `os.stat` fault then fires only on the pinned target-leaf diagnostic after that replacement. The test requires the original synthetic replace `OSError`, an explicit `post-error probe unavailable (OSError)` uncertainty note, published new bytes, intact external canary, and no temporary residue. The injected `os.stat` is restored in `finally`.
- **recurrenceGuard:** The CI-bound AST guard now requires the three-case loop, the installed `module.os.stat = reject_probe_stat` hook, the synthetic probe failure, and the primary-error uncertainty diagnostic. Two source-negative mutations independently remove the new scenario or disable its fault hook; both must fail closed. Existing direct invocation of `prove_atomic_replace_failure` from the test harness main remains mandatory.
- **retryCondition:** Revalidate if the replacement exception handler, post-error diagnostic probe, test hook, source-negative binding or temporary cleanup changes. Do not manually retry unchanged MinIO HTTP 401, workflow permission or external human evidence blockers.
