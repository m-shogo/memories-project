## Material failure

- **symptom:** The new pinned module importers silently ignored descriptor-close failures, and their first correction caught only `OSError`. This could treat an incompletely cleaned import as success, or allow a `ValueError` cleanup failure to replace an earlier primary rejection.
- **evidence:** Starting HEAD `8e91c49b` had `except OSError: pass` in both module importers' `finally` loops. The first correction [`c9069cee`](https://github.com/m-shogo/memories-project/commit/c9069ceefc6cd2491f6af1cf62a402d6ba4a7683) rejected post-effect `OSError` cleanup failure and preserved an earlier primary `Fail`; subsequent review of prior [non-OSError close learning](2026-11-01-upload-route-reader-non-oserror-close.md) identified the remaining `ValueError` class. No actual production close failure was observed.
- **rootCauseOrUnknown:** Verified exception precedence and an incomplete cleanup exception class. Real-world occurrence and descriptor state after arbitrary failed close are unknown; a raised close exception alone does not establish whether the descriptor was consumed.
- **failedApproach:** Silently swallowing close failures, followed by treating an `OSError`-only handler and one injected fault class as complete cleanup proof. The latter repeated a previously recorded exception-class gap and required correction.
- **correction:** [`c9069cee`](https://github.com/m-shogo/memories-project/commit/c9069ceefc6cd2491f6af1cf62a402d6ba4a7683) made a cleanup fault fail closed on an otherwise successful import without masking a primary error. [`745972af`](https://github.com/m-shogo/memories-project/commit/745972af621ec28f7784a1023fb08dacfc5b0e63) broadened ordinary cleanup exception preservation to `Exception`, including `ValueError`, in both importers.
- **recurrenceGuard:** The existing CI-reached binding reconcile negative suite runs both importers with isolated positive/symlink controls, post-effect `OSError` and `ValueError` close failures, and combined primary+cleanup failures. Each cleanup case asserts the expected fail-closed diagnostic, original primary-error precedence, and that the external execution marker was not written. Each numeric descriptor is closed at most once; uncertain close is never retried.
- **retryCondition:** Revisit only when descriptor ownership, Python cleanup exception behavior, module import implementation or exact-source negative CI changes. Do not retry unchanged MinIO HTTP 401, workflow permissions, production evidence or human promotion blockers.
