## Material failure

- **symptom:** A non-owning binary stream exposing a *different* file descriptor for the same inode could satisfy the canonical reader's pre/post `fstat(stream.fileno())` identity checks. The same issue existed when a synthetic stream switched to the alternate descriptor only after the initial read. This is an injected stream-boundary gap, not an observed production incident.
- **evidence:** At starting HEAD `1ce23650`, `read_canonical_authority_bytes` used `os.fdopen(fd, "rb", closefd=False)` but performed both `fstat` calls through `stream.fileno()` without proving that the returned integer was the exact `os.open` descriptor. A same-inode `os.dup(fd)` has identical file metadata, so inode comparison cannot establish descriptor ownership. The new real-FD fixtures use an independent external canary and verify raw/alias descriptor closure.
- **rootCauseOrUnknown:** Verified missing exact stream-to-owned-FD identity binding at acquisition and after the read. No evidence suggests ordinary CPython `os.fdopen` returns an alias; the synthetic wrapper models a malformed or substituted stream interface.
- **failedApproach:** Treating equal device/inode metadata as proof that the stream's descriptor is the owned raw descriptor, and checking identity only at initial acquisition.
- **correction:** [`726190bc`](https://github.com/m-shogo/memories-project/commit/726190bc4a4a56ed782bf1dbba93d6e3a6e9a0f3) requires a strict `int` `stream.fileno()` equal to the raw `fd` before the first `fstat`. [`eb75bf3e`](https://github.com/m-shogo/memories-project/commit/eb75bf3eb4df9542023ba1a50996016b03de3995) repeats that exact identity check after `read` and uses `os.fstat(fd)` at both snapshots. The existing non-owning stream cleanup and original-error preservation remain in place.
- **recurrenceGuard:** [`83a0e550`](https://github.com/m-shogo/memories-project/commit/83a0e5505eedaec549ec5ade504592df82065828) injects a same-inode alternate descriptor at acquisition; [`52ab66a5`](https://github.com/m-shogo/memories-project/commit/52ab66a56d632e964e56ab8537ff3318fcdfcfab) injects a stream that switches to the alternate descriptor after the first check. Both require exact fail-closed diagnostics, closed owned/alias FDs, intact independent canary and successful subsequent canonical read. They are executed by the existing CI-reachable negative validator, not merely documented.
- **retryCondition:** Revisit if `os.fdopen`/stream ownership, canonical descriptor snapshot order, read transport, CI negative-suite reachability or approved authority-file semantics change. Do not retry unchanged Quay MinIO HTTP 401 or workflow-write permissions without changed preconditions.
