## Material failure risk A — a staged inode could acquire an unreviewed hardlink

- **symptom:** The descriptor-relative Upload Route publisher created an exclusive pinned temporary file but did not reject a second hardlink added to that staging inode while writing. Its final stage identity compared type, device, inode, mode and ctime but not link count. A published file could therefore share its inode with an independent name. This is a source-verified latent failure class, not an observed production leak.
- **evidence:** At starting `so` `55b75c2f5f3868418821570735d81367a8e14738`, `atomic_write_bytes` called `os.fstat(handle.fileno())` after staged fsync and `os.stat(temporary.name, dir_fd=parent_fd, follow_symlinks=False)` before rename without requiring `st_nlink == 1`. Existing learning `2026-10-31-upload-route-hardlink-snapshot-and-write-guard.md` already required single-link identity for the distinct read/snapshot/target authority; that mechanism was reused at the staging boundary.
- **rootCauseOrUnknown:** Verified missing staged-file single-link predicates. Whether a hostile local principal could learn the unpredictable stage name or create a hardlink depends on directory ownership, permissions and filesystem rules; no deployed exploit is claimed.
- **failedApproach:** Treating exclusive `O_CREAT|O_EXCL|O_NOFOLLOW` creation and stable staged inode/ctime as proof of exclusive single-name ownership through publication.
- **correction:** [`621e528e`](https://github.com/m-shogo/memories-project/commit/621e528e27ef32a882eeec93abd0ab498a813710) requires a regular, single-linked stage after fsync and again at the descriptor-relative live stage check. The existing disposable poststage negative now injects a real `os.link` during fsync, requires exact staging-drift rejection, preserves original target bytes and the independent alias, and checks that the owned temporary name is cleaned.
- **recurrenceGuard:** The real negative runs from the existing pre-MinIO Upload Route guard. Its AST source binding requires the `os.link(staged[0], stage_alias)` injection, and two independent source mutations must reject weakening either staged `st_nlink == 1` predicate.
- **retryCondition:** Revisit only if staging, filesystem link semantics, permission trust boundaries, exact-source CI or the reviewed publication model changes. A check after fsync does not prevent a transient hardlink's earlier exposure, and a final check is **not** an atomic leaf CAS or a guarantee against link creation immediately before rename.
