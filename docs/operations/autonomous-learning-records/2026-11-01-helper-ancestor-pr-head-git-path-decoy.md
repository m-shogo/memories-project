## Material failure — PR-head positive-control Git lookup depended on inherited PATH

- **symptom:** The helper-ancestor CI reachability validator obtained its PR-head positive-control SHA using `subprocess.check_output(["git", "rev-parse", "HEAD"])`, so an inherited PATH could select a decoy executable. This is an observed source-level executable identity gap; no real CI compromise, forged production evidence or successful bypass is asserted.
- **evidence:** At HEAD `d572a97a`, the live `prove_ancestor_pr_head_negative` function used bare `git` to establish the expected source SHA. An isolated PATH-decoy shell positive control demonstrates that a PATH-first fake `git` can return a syntactically valid but false 40-hex SHA. The later reviewed shell comparison may still reject that false SHA; this gap must not be misreported as a demonstrated admission bypass.
- **rootCauseOrUnknown:** Verified reliance on inherited PATH for a trusted executable identity. Actual adversarial control of CI PATH is unknown and not asserted.
- **failedApproach:** Treating a syntactically valid 40-hex Git SHA from an unpinned executable as sufficient positive-control authority.
- **correction:** [`601e4ee9`](https://github.com/m-shogo/memories-project/commit/601e4ee96cf4b89ed61f887ceac14fca735a0026) pins the positive-control command to the reviewed `/usr/bin/git` binary. The existing PR/push/dispatch shell authority, exact HEAD comparison and malformed PR-head negatives remain unchanged.
- **recurrenceGuard:** The CI-reachable `prove_ancestor_pr_head_negative` now creates a disposable executable named `git`, prepends its directory to PATH, proves naive lookup returns the false 40-hex SHA, and while the decoy remains active requires the pinned command to return a different genuine SHA. It restores PATH and removes the temporary executable before the existing shell positive and negative cases run. Reverting the live command to bare `git` would make this positive proof fail.
- **retryCondition:** Revisit if the reviewed runner no longer provides root-owned `/usr/bin/git`, if shell Git resolution or the PR-head proof changes, or if exact-source CI regresses. Do not retry unchanged MinIO HTTP 401, workflow-write permission or missing human approval blockers.
