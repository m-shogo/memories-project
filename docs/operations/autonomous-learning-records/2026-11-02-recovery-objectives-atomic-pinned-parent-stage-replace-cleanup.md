- **symptom:** The recovery-objectives reconciler's atomic writer could stage, replace, or clean a temporary file through a mutable parent pathname after initial review; a directory rename/symlink swap between the final path check and `os.replace` could target a different directory or strand a staged inode.
- **evidence:** At starting `so` HEAD `c6bcdb8571a83fb21cbc7d6064d6dc8a82c4f465`, `scripts/reconcile-memory-os-recovery-objectives.py::write_text` used `tempfile.mkstemp(dir=path.parent)`, `os.replace(temp_name, path)`, and `os.unlink(temp_name)`. The precommit parent-swap negative explicitly removed a stranded temporary inode after restoring the parent. These are source/fixture observations, not an observed production attack.
- **rootCauseOrUnknown:** Verified pathname re-resolution of stage/replace/cleanup and no owned parent FD for the final syscall. Whether an attacker ever exercised the race is unknown. A directory can still be swapped and restored around visibility checks; complete adversarial atomicity across directory renames is not claimed.
- **failedApproach:** Treating a precommit pathname identity check as sufficient protection for a later pathname-based `os.replace`, and cleaning through the same potentially swapped pathname.
