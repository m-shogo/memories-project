## Material failure class and executable correction

- **symptom:** After an `os.fdopen` handoff failure, the diagnostic `os.fstat(descriptor)` could raise a non-`OSError` ordinary exception such as `ValueError`. The earlier `except OSError` would mask the primary `fdopen` failure and bypass its bounded ownership-unknown note.
- **evidence:** At source HEAD `76bafad7`, the failed-handoff handler caught only `OSError as probe_exc`. The existing disposable probe-fault suite injected only `OSError` while the caller required the original `synthetic fdopen failure` to survive. This is an identified source/test coverage gap, not a production incident.
- **rootCauseOrUnknown:** Verified mismatch between the diagnostic exception class and the primary-error-preservation invariant. Whether real `os.fstat` raises `ValueError` for a valid integer FD under ordinary OS operation is unknown; the negative explicitly injects it.
- **failedApproach:** Assuming that every ownership diagnostic failure is an `OSError` and testing only that class. During patch preparation a broad string replacement also matched two test branches; it was rejected before any repository write, then scoped to the existing probe-test function rather than replacing an ambiguous occurrence.
- **correction:** [f9987ab9](https://github.com/m-shogo/memories-project/commit/f9987ab9fdb2089b6bc4aa4da5bab37ef914e486) changes only the failed-handoff ownership probe to `except Exception as probe_exc`. It preserves the primary `fdopen` exception and bounded diagnostic while retaining the no-close rule. `BaseException` cancellation signals remain outside this new catch.
- **recurrenceGuard:** [86778435](https://github.com/m-shogo/memories-project/commit/8677843538dc6d465c5462ad715d8e3ce2307cb0) expands the isolated owned/reused probe-fault matrix from two to four cases, injecting `ValueError` as well as `OSError`, preserving original bytes, mode, independent canary, staged-name cleanup and numeric FD ownership. [01ae72c7](https://github.com/m-shogo/memories-project/commit/01ae72c7d39e7e036539ac43b98c799de868df33) extends the CI AST and source-negative mutations to require the four-case loop and reject narrowing the handler back to `except OSError`. The existing 4,096-line CI entrypoint budget is unchanged.
- **retryCondition:** Revisit on changes to diagnostic exception handling, fdopen/descriptor semantics, source-negative binding or Python runtime behavior. Do not generalize this to arbitrary `BaseException` suppression or claim atomic FD ownership. Do not retry unchanged external MinIO HTTP 401 or workflow-write permission failures.
