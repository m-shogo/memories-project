## Material failure

- **symptom:** The two pinned Python module importers accepted an `os.open` result into the owned descriptor list without first checking exact integer type and nonnegative range. The first newly added negative test also failed in CI because its leaf acquisition ordinal was wrong.
- **evidence:** At starting `so` HEAD `8565df44`, both `load_module` implementations appended root/ancestor/leaf `os.open` returns directly. Initial [code commit 5b0c6aed](https://github.com/m-shogo/memories-project/commit/5b0c6aedf10ab3a6e74c1ad5ad9be787e2f5fc25) added strict guards and synthetic cases, but exact-source [Binding CI #41343712110](https://github.com/m-shogo/memories-project/actions/runs/41343712110) **FAILED** with `module acquisition ownership/cleanup drift`. - **rootCauseOrUnknown:** Verified two distinct causes: missing pre-ownership FD validation in both new importers; and a test fixture using `len(approved.parts)` (absolute pathname component count) rather than the actual `os.open` call count (one ROOT FD, one relative `pkg` parent, one leaf). The synthetic leaf injection therefore never occurred. No malformed real CPython syscall return or production compromise was observed.
- **failedApproach:** Treating successful `os.open` invocation as proof of a valid owned descriptor, then using absolute path depth to infer a pinned relative acquisition sequence. The fixture's final cleanup assertion masked the more specific missed injection.
- **correction:** [5b0c6aed](https://github.com/m-shogo/memories-project/commit/5b0c6aedf10ab3a6e74c1ad5ad9be787e2f5fc25) checks `type(fd) is int and fd >= 0` before every owned append in both importers. - **recurrenceGuard:** Existing CI-reached binding reconcile negative suite injects `None`, `True`, `-1`, `1.5` and `"7"` at root, intermediate ancestor and leaf acquisition. It requires the exact fail-closed diagnostic, each previously acquired real FD closed once, no unowned/recycled FD close, a surviving external FD canary, and no execution of untrusted marker code. Both validator and reconciler importers run the same cases; earlier path-swap, hardlink, size, short-read, EOF, nonbytes and cleanup-double-fault cases remain.
