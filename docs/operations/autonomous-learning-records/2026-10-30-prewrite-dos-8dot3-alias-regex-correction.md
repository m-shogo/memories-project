- **symptom:** The prewrite path grammar accepted Win32 DOS 8.3 short-name shapes such as `docs/LONGFI~1.TXT` and `scripts/PROGRA~2/config`, which can alias longer filenames when 8dot3 name generation is enabled. During the first implementation, a source inspection found a doubled regex backslash before the extension dot.
- **evidence:** Prior code had no 8dot3 component check. Initial [`b09b4f0e`](https://github.com/m-shogo/memories-project/commit/b09b4f0ef50eb7beb6e561bc3dd96ee8105c45de) contained two literal backslashes in a Python raw regex, verified by reading the committed source and character codes `92,92,46`; that would not recognize a normal `.TXT` extension. This was caught **before** an exact-source CI run; no production incident is claimed.
- **rootCauseOrUnknown:** Verified missing short-name alias check, plus a JS-to-Python escaping-layer mistake that generated an incorrect raw regex.
- **failedApproach:** Treating 8dot3-shaped paths as independent file identities and assuming a generated raw regex had the intended number of backslashes without inspecting its committed bytes.
- **correction:** [`b09b4f0e`](https://github.com/m-shogo/memories-project/commit/b09b4f0ef50eb7beb6e561bc3dd96ee8105c45de) added conservative 8dot3 rejection; [`9ea981f3`](https://github.com/m-shogo/memories-project/commit/9ea981f39048641ae5aa7b44e7f33cab8b7c1685) corrected the regex to one literal backslash before the dot; [`c076afc5`](https://github.com/m-shogo/memories-project/commit/c076afc55d68d04c2c97c6a7310c56c3cf7dc6d3) added real CLI negatives.

Positive controls preserve `docs/notes~draft.md` and `docs/longfi~0.txt`. Always inspect the actual committed raw-regex source, and test both extension-bearing and extensionless aliases before accepting generated regex patches.
