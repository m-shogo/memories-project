## Material failure: symptom, evidence, root cause, failed approach, correction, recurrence guard, retry condition

- **Symptom:** Even after normalizing quoted top-level `on`, the prewrite workflow fanout scanner still missed valid nested quoted event keys such as `on:\n  'push':` and `on:\n  "pull_request":`. This is a static false-negative risk, not an observed production incident.
- **Observed evidence:** The previous scanner matched `^  push:` and `^  pull_request:` literally, while YAML accepts quoted mapping keys. The prior fourteen synthetic cases did not exercise quoted nested events.
- **Verified root cause:** The event-block regex normalized the outer YAML key but did not normalize the inner event mapping keys. Consequently a workflow that should match a changed path could be omitted from the prewrite blast-radius classification.
- **Failed approach:** Treating normalization of only the outer `on` key as complete YAML event-key support. This is a new precondition/fixture gap, not a retry of an unchanged external blocker.
- **Correction:** [3d5572e0](https://github.com/m-shogo/memories-project/commit/3d5572e04bdfef91d5596541afe6416b3988d169) conservatively normalizes quoted nested `push`/`pull_request` keys and adds two synthetic positive cases. - **Executable recurrence guard:** Sixteen synthetic cases and five actual CLI event fixtures (quoted top-level, scalar push, quoted nested push, quoted nested PR, dispatch-only nonmatch) now run on exact source via the Autonomous Learning Guard. A matched workflow count of zero for the nested quoted cases fails CI.
- **Retry condition:** Revisit when GitHub Actions event grammar changes, a new YAML form is observed, or the scanner's actual CLI fixtures regress. Do not retry unchanged MinIO HTTP 401, large canonical-learning HTTP/2 append, or workflow write-permission blockers.
