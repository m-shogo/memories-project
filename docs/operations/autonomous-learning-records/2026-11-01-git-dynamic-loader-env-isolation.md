- **symptom:** The supplemental history validator invoked the trusted `/usr/bin/git` with an environment that stripped inherited `GIT_*` but still forwarded `LD_*` and `DYLD_*`. The executable path was pinned, but its dynamic-loader environment was not.
- **evidence:** Source inspection of `scripts/validate-autonomous-learning-records-history.py` at `6f3301ff` showed the `GIT_*`-only filter. A separate Linux subprocess positive control with `LD_DEBUG=libs` produced 1,397 stderr bytes from `/usr/bin/git --version` despite exit code 0. This proves inherited loader settings can affect a pinned Git invocation; no actual malicious library, compromised runner or bypass was observed.
- **rootCauseOrUnknown:** Verified inherited dynamic-loader environment crossing the Git subprocess trust boundary. Real-world adversarial control is unknown.
- **failedApproach:** Treating the pinned Git binary and `GIT_*` sanitization as sufficient executable identity and transport protection.

The existing pinned executable, strict exit/bytes/OID checks, complete history traversal and fail-closed behavior remain in place.
