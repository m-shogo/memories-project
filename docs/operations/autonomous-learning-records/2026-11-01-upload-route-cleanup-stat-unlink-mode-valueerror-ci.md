## Material failure — secondary cleanup exceptions could replace a primary publication error

- **symptom:** A non-`OSError` ordinary exception (for example `ValueError`) from staged-name `os.stat` or `os.unlink` during a failed publication was not handled by the previous narrow cleanup handlers, so it could replace the primary publication error. This was a verified source-level exception-coverage gap, **not** a production incident.
- **evidence:** At starting code HEAD `4fdfcbf3`, `atomic_write_bytes` used `except OSError as cleanup_exc` and `except OSError as unlink_exc`; the existing disposable stat/unlink negatives injected `PermissionError` only. [`0523df36`](https://github.com/m-shogo/memories-project/commit/0523df369a5c2b2eeb545cfb144114fa60712a09) widened both handlers to `Exception`, and [`6d6bc5ce`](https://github.com/m-shogo/memories-project/commit/6d6bc5ced1b520c2223f60fb66fac2552691d4a2) exercised stat `PermissionError`/`ValueError` plus unlink before/after-effect `PermissionError`/`ValueError`, retaining primary error, bounded diagnostic, original bytes/mode, independent canary, and unverified stage-name safety.
- **rootCauseOrUnknown:** Verified: cleanup catch clauses covered only `OSError` subclasses. An ordinary exception of another type bypassed original-error preservation; the actual completion of a raising unlink remains unknown without independent observation.
- **failedApproach:** Relying on OSError-only cleanup proof, or treating `os.stat` followed by `os.unlink` as an atomic ownership CAS. The latter is **not** established by these tests.
- **correction:** Preserve the original publication exception across ordinary cleanup failures with `except Exception`; never retry an ambiguously completed unlink or infer pathname ownership without the existing staged identity checks.
- **recurrenceGuard:** [`235dc499`](https://github.com/m-shogo/memories-project/commit/235dc499be97ac1aa6a6811cfff32a508a368bdc) bound the real stat/unlink case matrix and weakening mutations to the existing CI-reached read-only entrypoint; the final guard also rejects narrowing either runtime handler back to `OSError`.
- **retryCondition:** Revisit only if cleanup stat/unlink behavior, identity ownership, original-error handling, test matrix or CI source-negative binding changes. Do not retry an unchanged external MinIO or workflow permission blocker.
