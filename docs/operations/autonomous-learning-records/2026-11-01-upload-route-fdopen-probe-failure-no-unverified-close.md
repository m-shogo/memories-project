## Material failure class — ownership probe cannot be assumed reliable

- **symptom:** A failed `fdopen` acquisition may be followed by an `fstat` failure on its numeric descriptor, whether the staged FD is still open or has been closed and reused. Closing it after the failed probe would risk consuming an unrelated FD. This is an exceptional-path risk and a previously missing executable proof, not an observed production incident.
- **evidence:** Source at `d3198974` already adds `fdopen stage descriptor ownership unverified` to the original error and skips a close after `fstat` raises. There was no direct two-case negative verifying this behavior. [`bbd88606`](https://github.com/m-shogo/memories-project/commit/bbd886068b7db45ee89b48b7a68c82190b86ccb9) adds isolated `owned-probe-fault` and `reused-probe-fault` scenarios; the latter recycles the staged FD number for an independent canary before forcing the ownership probe to raise.
- **rootCauseOrUnknown:** Verified test coverage gap; a failed ownership probe cannot distinguish an open original stage FD from a recycled descriptor. Whether a real FD was consumed remains explicitly unknown without independent observation.
- **failedApproach:** Treating a failed `fstat` as permission to retry or close an unverified numeric descriptor, or masking the original fdopen error with the probe failure.
- **correction:** Keep the existing fail-closed behavior: preserve the original fdopen error, add a bounded ownership-unknown note and skip the unverified close. The owned pre-effect case can leave an unlinked FD open; only the disposable test reclaims it after restoring injected hooks. No leak-free guarantee is asserted.
- **recurrenceGuard:** The existing pre-MinIO CI entrypoint now AST-binds the live two-case loop, actual `module.os.fstat = fail_fdopen_ownership_probe` fault and `module.os.close = track_unverified_close` assertion. Source-negative mutations reject removal of either hook or narrowing to one case. Original bytes/mode, independent canary bytes, FD identity and staged-path residue are checked.
- **retryCondition:** Revalidate on changes to fdopen ownership, fstat probe, stage identity, cleanup, Python FD semantics or CI reachability. Never retry an unchanged unknown-ownership close. This remains a bounded diagnostic protocol, not an atomic FD CAS.
