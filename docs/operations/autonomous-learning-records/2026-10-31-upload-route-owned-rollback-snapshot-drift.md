## Material failure: latent rollback overwrite of independent changes

- **symptom:** The Upload Route rollback restored every captured file even when the reconciler had never modified it. An unrelated concurrent edit after snapshot could be overwritten during failure recovery. This was source-proven latent behavior, not an observed production overwrite.
- **evidence:** Prior `rollback_authority_files` iterated all `ROLLBACK_SNAPSHOT.items()` and called `atomic_write_bytes(path, original)` for each existing snapshot entry, without an owned-write inventory or comparing current bytes to the last reconciler write. A disposable local Python reproduction confirmed the corrected algorithm preserves an independent untouched edit and rejects an edited owned target before partial rollback.
- **rootCauseOrUnknown:** Verified: snapshot membership was treated as rollback ownership; the atomic writer lacked an expected-before-write byte comparison.
- **failedApproach:** Treating all scanned files as safe to restore, regardless of whether this invocation wrote them or whether an independent writer advanced the file.
- **correction:** [10f73e52](https://github.com/m-shogo/memories-project/commit/10f73e52e7f4c5b78b23e152639597a428692028) adds `ROLLBACK_WRITTEN`, reset at the start of `main`. Successful atomic publications register their exact bytes; writes absent from the snapshot and writes against stale snapshot bytes fail closed. Rollback preflights tracked current bytes and restores only owned paths, rejecting a concurrent edit before restoring any entry.
- **recurrenceGuard:** The existing rollback negative now exercises actual atomic publications rather than untracked direct fixture edits. A new `prove_rollback_write_ownership` fixture covers untouched independent edits, owned-target concurrent drift with no partial restore, stale prewrite bytes and untracked new paths. The existing entry-document CI validator AST-binds this negative and the symlink negative as direct `main` calls, with both rollback and atomic-write transports exercised.
- **retryCondition:** Revisit after changes to snapshot capture, atomic publication, rollback ownership, path aliases or the CI negative call graph. A path-level check still has a filesystem race between the byte check and `os.replace`; no directory-fd or exclusive lock proof is claimed.
