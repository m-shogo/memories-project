## Material failure — parent swap before pinned acquisition returned an unclassified OS error

- **symptom:** The newly pinned owned-new-file rollback path guarded parent/leaf identity after opening, but a parent rename plus symlink swap **at** `os.open(parent, O_DIRECTORY|O_NOFOLLOW)` raised a raw OS exception instead of a fixed `ReconcileFailure`. A vanished parent/leaf at `lstat`/`stat(dir_fd=...)` had the same unclassified diagnostic gap. This is a source-level failure-class gap, not an observed production incident or canary deletion.
- **evidence:** At code `b347ed78` and `so` `6d11325b`, `rollback_authority_files` directly called parent `os.open`, live-parent `lstat` and dirfd leaf `os.stat` without scoped OSError classification. Existing prior learning `2026-10-31-upload-route-pinned-new-file-unlink-parent-swap.md` already established the parent capability and the residual leaf race. A new disposable negative renames the owned parent and creates an external symlink **before the parent open**, requiring a fixed domain failure and untouched owned/external bytes.
- **rootCauseOrUnknown:** Verified missing fixed failure classification at three descriptor-relative rollback acquisition/stat boundaries. No evidence of an actual external write, and no proof of atomic leaf compare-and-delete.
- **failedApproach:** Assuming a no-follow `os.open` failure by itself was sufficient for stable, private, reusable rollback diagnostics.
- **correction:** [`4bc64830`](https://github.com/m-shogo/memories-project/commit/4bc64830d300ddfa5c6abf81e1206e8655725847) maps parent-open and parent-lstat `OSError` to `ReconcileFailure("concurrent rollback parent drift")`, and leaf dirfd stat errors to `ReconcileFailure("concurrent authority identity drift before rollback")`, suppressing raw exception context while always closing an acquired parent descriptor.
- **recurrenceGuard:** The actual rollback negative now injects the parent swap at `os.open`, checks the external canary and original owned file, and separately makes `O_DIRECTORY` unavailable to require a typed unsupported-capability rejection without a pathname fallback. [`26a2177f`](https://github.com/m-shogo/memories-project/commit/26a2177f94353157726f095f8ca066116fea2953) binds both live negative branches and the three `OSError` handlers to the existing pre-MinIO CI entrypoint, with source mutation negatives for removed injection, unsafe flag fallback and altered exception type.
- **retryCondition:** Revisit only if directory capability, parent/leaf stat behavior, exception classification, negative transport or CI binding changes. Do not repeat an unchanged raw parent-open failure path or claim that directory pinning solves the remaining leaf stat-to-unlink race.
