## Material failure — latent parent-path redirection during owned new-file rollback

- **symptom:** After full snapshot and owned-inode preflight, the Upload Route rollback removed newly created files using `if path.exists(): path.unlink()`. A concurrent parent rename plus symlink replacement between preflight and unlink could redirect the deletion into a different authority tree. This is a source-verified latent hazard, **not** an observed production deletion.
- **evidence:** At `so` `616a698ddce6c4e3f060438be2828d463d865f67`, `scripts/reconcile-memory-os-upload-route-authority.py` used pathname `Path.unlink` in the `original is None` branch. Prior append-only lesson `2026-10-31-upload-route-owned-identity-ci-closeout.md` explicitly left the pathname-check-to-unlink race unresolved. A new disposable filesystem negative renames the owned parent and replaces it with a symlink to a directory containing an external `created.txt` canary **at the unlink call**.
- **rootCauseOrUnknown:** Verified: preflight leaf ownership and bytes/ctime checks were not a pinned directory capability; the later pathname unlink could resolve a different parent. No external exploitation or production overwrite was observed.
- **failedApproach:** Treating earlier symlink checks and published leaf inode identity as sufficient to make a later pathname-based unlink safe.
- **correction:** [`b347ed78`](https://github.com/m-shogo/memories-project/commit/b347ed78ec29cabc49d5a8793c73cae7c7665d22) opens the parent with `O_DIRECTORY|O_NOFOLLOW`, checks the live parent device/inode against its pinned descriptor, validates the owned leaf's device/inode/mode/ctime through `os.stat(..., dir_fd=parent_fd, follow_symlinks=False)`, and deletes via `os.unlink(path.name, dir_fd=parent_fd)` with descriptor cleanup. This confines the deletion to the opened parent even if its pathname is subsequently redirected.
- **recurrenceGuard:** The same commit adds a deterministic real-filesystem race injected at the actual `os.unlink` transport. It requires the original owned file to be removed while the external canary remains byte-identical and the live parent is a symlink. [`d2d3d5f`](https://github.com/m-shogo/memories-project/commit/d2d3d5f76807b46d021c7f2e7c660bf06d93978d) extends the existing pre-MinIO CI entrypoint to bind the live injected `os.unlink` scenario and the actual pinned `os.open`/`os.stat`/`os.unlink` code, with deterministic source mutations rejecting unpinned deletion and a missing injection.
- **retryCondition:** Re-evaluate when parent/leaf publication or rollback semantics, platform dir-fd support, CI invocation, or a new adversarial race changes. This is **not** an atomic leaf compare-and-delete: an uncooperative writer can still swap a leaf between `fstatat` and `unlinkat`. Full write-side ancestor traversal and `os.replace` publication remain separate review targets. Do not repeat a known pathname-only unlink without a changed precondition.
