## Material failure — same-inode numeric FD reuse defeated prior cleanup ownership inference

- **symptom:** A failed `os.fdopen(descriptor, "wb")` could close the original numeric descriptor, after which an independent opener could reuse that number for the **same inode**. The previous cleanup then closed that independently owned descriptor.
- **evidence:** Prior disposable same-inode POSIX reproduction and append-only record `2026-11-01-upload-route-same-inode-fd-reuse-boundary.md` at source HEAD `99004159` identified the false-positive `(st_dev, st_ino)` predicate. The reconciler previously invoked `os.close(descriptor)` after a matching `fstat` in its `fdopen` exception handler. This is a verified source-level failure class, not an observed production incident.
- **rootCauseOrUnknown:** Verified: device/inode equality proves underlying file identity, not ownership of a numeric file descriptor. No atomic FD ownership CAS is available in this protocol; real-world occurrence remains unknown.
- **failedApproach:** Conditional `os.close(descriptor)` after an `fstat` inode match; different-inode canary and failed-probe tests alone could not rule out same-inode reopening.
- **correction:** [7f40585f](https://github.com/m-shogo/memories-project/commit/7f40585f7873fe84c27b29594e215a0d5bea8be5) removes the close from the failed-handoff branch. Matching-inode, changed-inode and failed-probe cases now retain the primary `fdopen` error, add a bounded ownership diagnostic and skip the uncertain close. `untransferred_stage_fd = None` prevents a second uncertain close in the outer `finally`.
- **recurrenceGuard:** [b6078a55](https://github.com/m-shogo/memories-project/commit/b6078a5581d576fdf625dd6d17e904d6a4497e64) extends the existing disposable filesystem negative with an independent **same-inode** reopened FD and an external canary, checking original authority bytes/mode, stage-name cleanup, primary exception, diagnostic and live replacement FD. Pre-effect failure and before/after close-hook cases explicitly prove no ambiguous close. [e3f3e141](https://github.com/m-shogo/memories-project/commit/e3f3e1416eb7193de537283dfad4d40b52c3c25b) binds the four-case loop to the existing CI AST/source-negative guard and rejects a reintroduced `os.close(descriptor)` in the failed `fdopen` handler. [0ab98f2c](https://github.com/m-shogo/memories-project/commit/0ab98f2c289ec707cf86d4ce83ff7dbf2ab5515f) respects the prewrite line cap.
- **retryCondition:** Revisit on changes to Python `fdopen` handoff semantics, descriptor duplication/ownership, stage cleanup or CI binding. A pre-effect failed `fdopen` may leave an **unlinked open FD** because no safe ownership proof exists after ambiguous handoff; do not claim leak freedom. Next design an explicit retained-original/duplicated-handoff protocol with disposable pre/post-effect negatives before changing it. Do not retry unchanged MinIO HTTP 401 or workflow-write blockers.
