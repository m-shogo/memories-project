## Material execution failure — tool-call ceiling before ref publication

- **Symptom:** An orchestration constructing the hardlink-authority guard's Git blobs, tree and candidate commit failed with `Code Mode exceeded the maximum number of tool calls` before the branch-ref update executed. The candidate Git commit existed, but there was no verified branch publication.
- **Observed evidence:** The connector had returned validator blob `dda12821`, negative blob `6b2fe6f6`, tree `aaee05b8`, and candidate commit `e6c9ef9b4dd14eb5a7d7ea7755a53da1d70a0d89`. A separate branch read still returned prior HEAD `edbcf442e1d2148cb310bc0416534c69f3ecd1c8`. An initial recovery read using the wrong normalized commit payload field returned an undefined parent and correctly stopped before any ref write. The Git-data commit endpoint then verified the candidate's actual parent as `edbcf442...`.
- **Verified root cause or explicit unknown:** The immediate failure was the orchestration's connector tool-call budget. Its exact ceiling is unknown. The initial recovery stop was a local response-shape assumption (`fetch_commit` wrapper rather than Git-data commit JSON), not a GitHub repository failure.
- **Failed approach:** Packing too many independent reads, blob/tree/commit creations and final ref publication into one orchestration, then initially looking for the candidate parent in the wrong response field.
- **Correction:** Split remote Git-object operations into bounded calls; before ref publication, independently re-read `so` and both target file blob SHAs, fetch the candidate through the Git-data commit endpoint, verify its parent, and apply `update_ref` with `expected_sha` and `force=false`. The branch advanced to `e6c9ef9b...` only after this proof.
- **Recurrence guard:** Existing executable GitHub compare-and-swap `expected_sha` prevents stale publication; separate head/target/parent reads prevent treating a dangling candidate as an applied change. Reuse prior `2026-10-30-workflow-inventory-connector-call-budget.md` learning: do not repeat unbounded connector fanout. **No new repository-level validator for the connector call ceiling was added**; do not claim otherwise.
- **Retry condition:** Retry publication only if the candidate Git commit is readable, its parent matches the freshly observed branch HEAD, both target blobs are unchanged, and the CAS lease is valid. If any precondition changes, stop and reconcile; do not force-update or repeat the same bulk orchestration.
