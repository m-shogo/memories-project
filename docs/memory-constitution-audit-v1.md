# Memory Constitution Audit v1

## 目的

`docs/memory-constitution-v1.md` を、既存の信頼できる原則と照合し、抜け漏れ・曖昧さ・衝突し得る箇所を洗い出す。

この監査は、憲章を「よさそうな理念」で終わらせず、実装・UI・AI応答・インポート・課金判断に使える上位ルールへ育てるためのもの。

## 参照した外部原則

### AI倫理・AIガバナンス

代表的なAI倫理ガイドラインでは、以下の原則が繰り返し現れる。

- 透明性
- 説明可能性
- 責任
- 安全性
- プライバシー
- 公平性
- 人間中心
- 人間の主体性
- 堅牢性
- 悪用防止

採用方針:

- 記憶体では「人間中心」を「その人の文脈が最優先」と読む。
- 「透明性」は、記憶の出典・推測・確信度を表示することとして実装する。
- 「安全性」は、過去ログの有害な再生を避けることまで含める。

### 医療倫理

基本原則:

- 自律尊重
- 善行
- 無危害
- 公正

採用方針:

- 自律尊重: 保存・削除・非表示・共有・エクスポートをユーザーが決める。
- 善行: 記憶体は自己理解や人生文脈の保持に寄与する。
- 無危害: 危険な過去発言を現在の助言として返さない。
- 公正: 特定の属性、文化、家族形態、人生選択を劣ったものとして扱わない。

### トラウマインフォームドケア

中心原則:

- Safety
- Trustworthiness
- Transparency
- Peer support
- Collaboration
- Empowerment
- Voice and choice
- Cultural / historical / gender issues

採用方針:

- 記憶体は、過去を勝手に掘り返さない。
- 高感度記憶は、原文表示ではなく安全要約をデフォルトにする。
- ユーザーが扱う範囲を選べるようにする。
- 文化・時代・家庭背景を考慮し、現在の一般論で過去を裁かない。

### カウンセリング・心理支援

参考原則:

- 非判断
- 傾聴
- 自己決定
- ラベリング回避
- 境界の明確化

採用方針:

- 記憶体は相談AIではないため、治療的な介入を主目的にしない。
- ただし応答姿勢は、非判断・断定回避・自己決定尊重を守る。

### グリーフケア

参考原則:

- 喪失を急いで意味づけしない
- 故人を置き換えない
- 悲しみを否定しない
- 継続する絆を尊重する

採用方針:

- 「亡くなった人と話せる」と見せない。
- 「故人ならこう言う」と断定しない。
- 残された記録から、価値観や思い出を整理する。

### 回想法・ライフレビュー

参考原則:

- 安全に振り返る
- 本人のペースを尊重する
- 記憶の意味づけを尊重する
- 不快な記憶を無理に出さない

採用方針:

- Tipで高感度記憶を突然出さない。
- ユーザーが選んだ範囲から振り返れるようにする。

### プライバシー・データ保護

中心原則:

- 目的限定
- データ最小化
- 正確性
- 保存期間の制限
- 安全性
- 削除権
- アクセス権
- ポータビリティ

採用方針:

- 全文保存ではなく、意味のある要約・参照・確信度を残す。
- 原文保存はオプトイン寄りにする。
- 削除した記憶は検索、Embedding、Tip、派生要約からも外す。

## 現在のv1で良い点

### 1. 目的の境界が明確

v1は、以下を明確に否定している。

- 一般AI代替
- 人格AI
- パスワード管理
- 会社の便利検索
- 生データ倉庫

これは重要。ここが曖昧だと、サービスはすぐ便利ツール化する。

### 2. ユーザーの権利がある

削除、修正、非表示、AIに送らない、持ち出す、拒否するなどが入っている。

これはプロダクト信頼の土台になる。

### 3. 診断しない・原因断定しないが入っている

医療・心理の境界として重要。

### 4. 危険な過去発言を再生しない

「過去の自分なら死ねと言う」のような返答を防ぐルールがある。

### 5. 忘却の設計が入っている

記憶体サービスでありながら、忘れる・薄める・隠すを設計対象にしている点は強い。

## v1の不足・補強すべき点

### Gap 1: ルール衝突時の優先順位が弱い

例:

- 正確性 vs 安全性
- 原文アクセス権 vs 有害表現の非表示
- 家族共有 vs 他人のプライバシー
- エクスポート権 vs 第三者秘密

v2では明確な優先順位が必要。

推奨順:

1. 現在の安全
2. 第三者の重大なプライバシー
3. ユーザーの自律性
4. 正確性
5. 利便性
6. エンゲージメント
7. 収益

### Gap 2: 未成年・子どもの扱いがまだ薄い

必要な追加:

- 子どもの記録は高感度デフォルト
- 親が子どもの人生を勝手に固定しない
- 将来の本人に不利益な記憶を残しすぎない
- 家族共有時に子どものプライバシーを優先

### Gap 3: パートナー・LINE・他人の同意問題が薄い

必要な追加:

- LINEやDMは共同の会話であり、完全にユーザーだけの所有物ではない
- 相手の秘密や病気、悩みは記憶体の価値にしない
- 人物カードは相手の診断ではなく、ユーザーから見た関係性に限定

### Gap 4: 家族共有・死後共有の権限モデルが未定

必要な追加:

- 生前設定
- 死後アクセス条件
- 見せる範囲
- 見せない記憶
- 家族間で衝突した場合
- 削除権の所在

MVPでは実装しないが、憲章には「軽く扱わない」と明記する必要がある。

### Gap 5: 政治・宗教・性的指向・ジェンダー・文化の扱い

必要な追加:

- 記録から属性を推測しすぎない
- 本人が明示していない属性ラベルを作らない
- 家族や文化背景を現在の価値観で裁かない
- 差別的な過去発言は、原文再生ではなく時代・文脈・害の可能性を踏まえて扱う

### Gap 6: AIコンパニオン・AI恋人の依存領域

必要な追加:

- 恋愛的・依存的ログを恥として扱わない
- ただし美化もしない
- キャラクターやAIの発言を現実の愛情として保存しない
- ユーザー側の感情・創作・支えとして扱う

### Gap 7: 記憶の品質基準がまだ抽象的

必要な追加:

- Meaning Score
- Evidence Score
- Sensitivity Score
- Third-party Risk Score
- Future Harm Score

保存する・要約だけ・非表示・削除推奨を機械判定できるようにする。

### Gap 8: Red Team視点が足りない

必要な追加:

- 元恋人監視
- パートナーのLINE無断インポート
- 子どもの支配
- 故人への依存
- 会社機密の投入
- 自己否定ログの再提示
- 家族を責める材料として使用
- 大量インポートによるコスト攻撃

### Gap 9: 監査・ログ・説明責任

必要な追加:

- 何をAIへ送ったか
- 何を除外したか
- どのモデルで生成したか
- どの記憶がどの派生Tipや要約に使われたか
- 削除時に派生データも消えたか

### Gap 10: 憲章の改訂プロセス

必要な追加:

- 憲章変更時はCHANGELOGを残す
- 重大な安全ルール変更は破壊的変更として扱う
- ユーザーの記憶権利を弱める変更は禁止または明示レビュー必須

## v2で追加する章案

### 第九章: 優先順位と衝突解決

ルール同士が衝突した時の判断順。

### 第十章: 子ども・未成年

子どもの記録、親の記録、将来不利益、共有制御。

宗教、政治、ジェンダー、性的指向、健康、家族形態、文化背景。

## 実装に落とすべき必須チェック

### Import前

- ファイル一覧を表示する
- 危険カテゴリを推定する
- DM/LINE/Gmail/写真/会社データを識別する
- 秘密情報スキャンする
- 解析対象範囲をユーザーに選ばせる

### MemoryCandidate生成時

- Meaning Score
- Evidence Score
- Sensitivity Risk
- Third-party Risk
- Future Harm Risk
- Save Mode
- Quote Policy
- LLM Policy

を必ず持つ。

### 応答時

- 記録と推測を分ける
- 高感度原文を直出ししない
- 親・故人・過去の自分を演じない
- 診断しない
- 単一原因にしない
- 無理にポジティブ化しない

### 削除時

- Memory
- Embedding
- Tip
- Summary
- Person inference
- Topic inference
- Export cache

まで削除対象にする。

## v1評価

### 強み

- 方向性は正しい
- 人の文脈を最優先にできている
- 記憶体と人格AIを分離できている
- 安全要約・忘却・削除権が入っている

### 弱み

- まだ運用ルールとしては抽象度が高い
- 子ども・第三者・LINE・死後共有・Red Teamが薄い
- 実装データ構造との接続が不足
