# Product Principles

## 1. ChatGPT の代替にならない

このサービスは、長時間チャットを主目的にしない。

相談は ChatGPT / Claude / Gemini が担う。

このサービスは、相談結果や人生の断片を受け取り、長期記憶として整理する。

## 2. 入力ハードルを最小化する

最初から ZIP インポートや複雑なAPI連携を要求しない。

初回は以下のように軽く始める。

1. 診断
2. キャラクター誕生
3. 最初の記憶を1つ登録

過去データの一括インポートは、価値が伝わってから案内する。

## 3. 保存するのはログではなく文脈

チャット全文、写真本体、すべてのSNS投稿を無条件に保存するサービスではない。

保存対象は、長期的に意味が残る情報。

- 出来事
- 人物
- 場所
- 感情
- 価値観
- 判断基準
- 趣味の変化
- 人生の時期
- 元データへの参照

## 4. 勝手に人格を作らない

記憶が蓄積すると、その人らしさは自然に見えてくる。

しかし、サービス側が人格を過剰に演出しない。

特に、亡くなった人や家族の記録を扱う場合は、本人を再現しているように見せない。

常に「残された記録から推測する」という姿勢を守る。

## 5. あらゆるものから受け取れるが、最初から全部対応しない

強みは「対応サービス数」ではなく、**何でも受け取れる設計**。

最初に大事なのは、入力元を増やすことではなく、共通のインポートパイプラインを作ること。

- text
- url
- image metadata
- zip export
- json export
- pdf
- api records

これらを共通の memory candidate へ変換する。

## 6. 便利さより怖くなさ

常時監視、リアルタイム録音、画面解析、メッセージアプリの常時取得はやらない。

便利でも、怖いサービスになると使われない。

ユーザーが「これを覚えて」と渡したものを中心にする。

## 7. AIコストを体験単位で制御する

無制限チャットや無制限画像解析は危険。

料金はトークン数ではなく、ユーザーが理解できる体験単位にする。

- 深い人生分析
- 年間レポート
- 家族比較
- 大量インポート
- 画像解析

## 8. 全部保存しない。残すべきものを選ぶ

このサービスは保管庫ではなく編集者に近い。

大量ログをそのまま保存するのではなく、「10年後も意味がありそうな記憶」を候補化する。

ただし、AIが勝手に人生を書き換えているように見えないように、重要な記憶はユーザー承認を挟む。

## 9. 囲い込まない

会社が潰れてもユーザーの人生が失われない設計にする。

いつでもエクスポートできる。

元データを持たない場合でも、記憶の索引と要約を外へ出せる。

## 10. 日常利用と長期価値を両立する

死後に残せる価値は重要だが、それだけでは日常利用されない。

普段は、以下のような価値を出す。

- 最近の自分の変化
- 過去の自分との比較
- 人物ごとの記憶
- 趣味の変遷
- ランダムTip
- 去年の今日
- 忘れていた大事な出来事

長く使った結果として、家族へ人生の文脈を受け渡せるようにする。
