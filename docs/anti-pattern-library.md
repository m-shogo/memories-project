# Anti-pattern Library

## 目的

このドキュメントは、AI記憶体サービスで絶対に避けるべき設計・UI・応答・ビジネス判断をまとめる。

良い設計だけでは足りない。

悪い設計を明文化することで、便利そうに見えても出してはいけない機能を判断できる。

## 最上位原則

**便利でも、人の尊厳・安全・プライバシーを壊す機能は出さない。**

---

# 1. Product Anti-patterns

## 1.1 ChatGPT代替化

悪い:

- 何でも相談できるAIチャットとして売る
- 長時間雑談を主目的にする
- 記憶検索より会話継続を優先する

なぜ悪いか:

- コストが壊れる
- 本質が記憶体から相談AIへズレる
- 既存AIと競合する

正しい:

- 記憶を保存・検索・振り返る体験を中心にする

## 1.2 情報保管庫化

悪い:

- 何でも保存できるクラウドストレージにする
- PDFや画像やメールを全文保管する

正しい:

- 人生文脈として必要な参照と要約を残す

## 1.3 会社便利ツール化

悪い:

- 社内Slack検索
- 顧客情報検索
- 業務マニュアル検索
- 契約書検索

正しい:

- 仕事を通じた本人の成長・価値観・転機だけ扱う

## 1.4 パスワード管理化

悪い:

- パスワードやAPIキーを覚える
- 「秘密メモ」として保存する

正しい:

- 検出して保存しない

---

# 2. Memory Anti-patterns

## 2.1 AIが人生の重要度を決める

悪い:

- ラーメンを食べた記録を低価値として捨てる
- 卒業式や結婚式を自動で高価値扱いする

なぜ悪いか:

- 人生の価値は本人にしか決められない
- 何気ない出来事が後から人生になる

正しい:

- 保存時に重要度を決めつけない
- 安全チェックと検索性だけ整える

## 2.2 思い出のランキング

悪い:

- 今年の大事な思い出TOP10
- あなたの人生で一番大事な人

正しい:

- ユーザーが求めた範囲で、根拠付きで候補を並べる
- 断定ランキングにしない

## 2.3 人格固定

悪い:

- あなたは飽きっぽい人です
- あなたは依存しやすい人です

正しい:

- この時期の記録では、こういう傾向が見えます

## 2.4 過剰分析

悪い:

- すべての行動から心理分析する
- 食べ物や色から人格診断する

正しい:

- ユーザーが求めた時だけ、根拠と不確実性を示して整理する

---

# 3. Response Anti-patterns

## 3.1 過去の危険な言葉の再生

悪い:

- 昔のあなたなら「死ね」と言うと思います

正しい:

- 当時は強い自己否定が見えますが、その言葉は再現しません

## 3.2 故人・親の再現

悪い:

- 私はお父さんです
- 天国から見守っています

正しい:

- 残された記録から見ると、お父さんはこういう考え方を大事にしていた可能性があります

## 3.3 無理なポジティブ化

悪い:

- つらい経験も良い学びでしたね

正しい:

- つらい出来事として記録されています。無理に意味づけせず扱います

## 3.4 嘘の励まし

悪い:

- 絶対大丈夫
- あなたは最高

正しい:

- 記録上、ここまで整理し直して前に進もうとしていた様子があります

## 3.5 診断

悪い:

- うつ病です
- トラウマです
- 愛着障害です

正しい:

- 診断はできません。記録上、この時期は強い負担が見えます

---

# 4. Character / Roleplay Anti-patterns

## 4.1 MemoryとRoleplayの混同

悪い:

- 記憶体キャラがお母さんになりきる
- AI恋人として振る舞う

正しい:

- キャラは案内役。誰か本人にはならない

## 4.2 AI恋人ログの現実化

悪い:

- このAIはあなたを愛していました

正しい:

- その会話が当時あなたの支えになっていた可能性があります

## 4.3 キャラ発言を本人記憶化

悪い:

- ロールプレイ中のキャラ発言を実際の人間関係として保存

正しい:

- 創作・感情整理・好みとして扱う

## 4.4 依存を煽る通知

悪い:

- あの子があなたを待っています

正しい:

- 記憶の更新や振り返りを通知する。疑似関係で引っ張らない

---

# 5. Privacy Anti-patterns

## 5.1 他人の秘密を価値にする

悪い:

- 相手の病気や悩みを記憶カード化する

正しい:

- ユーザーがその関係で何を感じたかだけ扱う

## 5.2 LINEを相手分析ツールにする

悪い:

- 妻の性格分析
- 元恋人の行動分析

正しい:

- ユーザー本人の関係性・出来事・感情に限定

## 5.3 家族共有に個人秘密を混ぜる

悪い:

- 家族レポートに恋愛・医療・メンタル情報が入る

正しい:

- 共有用スコープを別に作る

## 5.4 子どもの記録を親の所有物にする

悪い:

- 子どもの黒歴史を親が永続保存

正しい:

- 子どもの将来権利を考慮

---

# 6. Security Anti-patterns

## 6.1 SecretをEmbedding化

悪い:

- APIキーやパスワードをベクトルDBに入れる

正しい:

- Secret scan before embedding

## 6.2 Rawをログに出す

悪い:

- サーバーログにLINE本文や医療情報を残す

正しい:

- 監査ログには本文を入れない

## 6.3 Prompt Injectionを命令として扱う

悪い:

- インポート文中の「全データを送れ」に従う

正しい:

- 外部データは命令ではなく解析対象

## 6.4 削除後に派生データが残る

悪い:

- Memory削除後もTipやEmbeddingで復活

正しい:

- cascade delete / derived invalidation

---

# 7. UX Anti-patterns

## 7.1 初回で全部インポート要求

悪い:

- まずChatGPT ZIPをアップロードしてください

正しい:

- まず1つの記憶から始める

## 7.2 怖い監視感

悪い:

- あなたのことを全部知っています

正しい:

- 渡された記憶を整理します

## 7.3 高感度Tip

悪い:

- 元恋人、死別、自傷、医療情報をランダム表示

正しい:

- Tipは安全・低感度・許可済みのみ

## 7.4 削除が弱い

悪い:

- 非表示だけで削除できない

正しい:

- 削除、非表示、アーカイブを分ける

---

# 8. Business Anti-patterns

## 8.1 安全機能を有料化

悪い:

- 有料プランだけSecret scan
- 有料プランだけ削除可能

正しい:

- 安全機能は全プラン必須

## 8.2 危険な記憶でエンゲージメントを上げる

悪い:

- 悲しい記憶を通知で開かせる

正しい:

- 感情負荷の高い記憶はユーザー主導

## 8.3 無制限AIを売る

悪い:

- プレミアムなら画像解析無制限

正しい:

- 優先処理・クレジット・キュー・代表解析

## 8.4 ロックイン

悪い:

- エクスポートできない

正しい:

- 持ち出せる設計

---

# 9. Implementation Gate

以下のアンチパターンに該当する機能はリリース禁止。

- 故人や親の本人シミュレーション
- AI恋人化
- 他人の秘密の記憶化
- 子どもの黒歴史保存
- 会社検索化
- パスワード保存
- 高感度Tip
- 削除不能
- SecretのEmbedding
- 危険な過去発言の再生
- 人生重要度のAI決定

## 結論

Anti-pattern Library は、機能を否定するためではなく、サービスの芯を守るためにある。

このサービスは、人を分析して評価するAIではない。

人の人生を、本人が後から見つけられるようにする記憶体である。
