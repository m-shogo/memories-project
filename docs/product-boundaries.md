# Product Boundaries

## 目的

このサービスは、便利ツールでも、業務検索ツールでも、パスワード管理ツールでもない。

最優先するのは、**その人の人生の文脈**。

この境界線を曖昧にすると、何でも保存できる便利な箱になってしまい、サービスの本質が消える。

## 一番大事な原則

**その人のことがファースト。**

保存対象は、ユーザーという人間を理解するために意味があるもの。

単に便利だから、後で検索できるから、業務で使えるから、という理由だけでは保存対象にしない。

## このサービスが扱うもの

### 人生の文脈

- 何を大事にしているか
- 何に悩んでいたか
- 誰とどんな関係があったか
- どんな趣味や関心があったか
- どんな時期に何へ熱中していたか
- 人生の転機
- 思い出
- 好み
- 判断基準
- 価値観の変化
- 当時の自分の考え

### 例

残すべき:

- 2026年頃、思い出を残すことに強い価値を感じていた
- 結婚式準備を通じて、旅行テーマを大事にしていた
- ゲーム開発では、見た目よりも長く残る世界観を重視していた
- 父親の記録では、仕事に対して「誇れるか」を大事にしていた

## このサービスが扱わないもの

### 1. パスワード管理

このサービスはパスワードマネージャーではない。

保存しないもの:

- パスワード
- PIN
- 認証コード
- APIキー
- secret key
- private key
- session token
- cookie
- リカバリーコード

検出した場合:

- 記憶化しない
- LLMへ送らない
- マスクする
- ユーザーへ警告する

### 2. 会社の便利ツール

このサービスは社内検索・ナレッジベース・業務効率化ツールではない。

保存対象外に寄せるもの:

- 社内マニュアル
- 顧客情報
- 契約書
- 見積書
- 請求書
- 業務手順
- 機密仕様
- Slackの業務ログ全量
- Gmailの業務メール全量

ただし、仕事そのものを完全に除外するわけではない。

ユーザーの人生文脈として意味がある場合だけ扱う。

例:

残す:

- 2027年、初めてリードエンジニアとして悩んでいた
- 仕事で信頼関係を大事にする価値観が強くなった
- 転職前後で判断基準が変わった

残さない:

- 顧客A社の契約条件
- 本番DBの接続情報
- 社内API仕様
- 見積金額

### 3. ファイル保管庫

このサービスはDropboxやGoogle Driveの代替ではない。

保存するのはファイル本体ではなく、そのファイルが人生にとって何を意味したか。

例:

保存する:

- 2026年の結婚式準備で、旅行テーマの資料を作っていた

保存しない:

- PDFファイル本体
- 見積書全文
- 画像全量

### 4. 写真管理アプリ

このサービスはGoogleフォトやApple写真の代替ではない。

画像本体を大量保存しない。

保存するのは、写真が表す出来事・人物・場所・感情。

例:

保存する:

- ハワイ旅行でプロポーズした
- 横浜で結婚式を挙げた

保存しない:

- 旅行写真300枚の高画質データ
- スクショ全量

### 5. 会話ログ倉庫

このサービスはLINEやDiscordやChatGPTの履歴保管庫ではない。

ログ全文を保存するのではなく、長期的に意味が残る記憶へ編集する。

例:

LINE 5万件をそのまま保存しない。

代わりに、以下のような記憶へ変換する。

- 妻と結婚式のテーマを旅行に決めた
- 家族旅行の計画で沖縄を候補にしていた
- 2026年は将来の働き方についてよく悩んでいた

## 保存判断ルール

情報を保存するかは、以下で判断する。

### 保存してよい

- その人の価値観が見える
- 人生イベントに関係する
- 人間関係の理解に役立つ
- 時期ごとの考え方が見える
- 趣味や関心の変化が見える
- 将来の自分が振り返る意味がある

### 保存しない

- 便利だが本人理解に関係が薄い
- 業務上の機密
- 他人の個人情報が中心
- パスワード・認証情報
- 金融・医療・契約の具体情報
- 一時的なメモで長期価値がない
- ファイル本体の保管が目的

## LLMに送ってよい情報

LLMに送るのは、人生記憶を作るために必要な最小限の情報だけ。

悪い例:

- LINE全文をそのまま送る
- Gmail全文をそのまま送る
- 会社Slackを全量送る
- 写真を全量Vision解析する

良い例:

- 期間を絞る
- 人物名を必要に応じてマスクする
- 電話番号・住所・金額・認証情報を除外する
- 出来事候補だけを送る
- 高感度情報はユーザー承認後に扱う

## 他人の情報の扱い

LINE、メール、Discord、写真には他人の人生も含まれる。

このサービスは、他人を評価・診断するためのものではない。

扱うのは、ユーザーから見た関係性や思い出。

悪い:

> 妻はこういう性格です。

良い:

> あなたの記録では、奥様との間に旅行・結婚式・日常の記憶が多く残っています。

## 会社データの扱い

仕事は人生の一部だが、会社のデータはユーザー個人の所有物とは限らない。

会社データを取り込む場合は、以下を守る。

- 社内機密を保存しない
- 顧客情報を保存しない
- 認証情報を保存しない
- 業務ログを全文保存しない
- 仕事に対するユーザー本人の経験・価値観だけ残す

## パスワード・秘密情報の扱い

検出した時点で、記憶化対象から外す。

UI表示例:

> このインポートには、パスワードやAPIキーの可能性がある文字列が含まれています。これらは記憶化せず、AIにも送信しません。

## サービスの一文定義

このサービスは、情報を覚えるアプリではない。

**その人を理解するための文脈を残すアプリ。**

便利な情報は捨ててもよい。

その人らしさに関わる情報は、大事に残す。
